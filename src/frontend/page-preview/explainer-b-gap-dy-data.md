# 页面交互差异 - dy-data（抖音经营数据引擎）

> 生成时间: 2026-07-20 12:05 +08:00
> Skill: page-explainer
> 最近复查: 2026-08-20（DYDATA-19 页面设计回环）
> 说明: GAP-P3-01、GAP-P3-02 保持范围外记录；GAP-P3-03 至 GAP-P3-06 是依据 DYDATA-19 已确认规格和真实浏览器运行证据识别的本轮设计差距。

## 差异清单

### GAP-P3-01: 普通管理员写权限尚未在全部后台模块统一收口

- **分类**: `out_of_scope`
- **所在页面**: 账号管理 (`/admin/accounts`)、商品分账规则 (`/admin/rules`)、数据同步 (`/admin/sync`)、商品口径控制 (`/admin/product-types`)
- **所在模块**: 后台写操作
- **所在元素**: 新建/保存账号、保存分账规则并重建、立即补拉、保存商品口径等
- **证据来源**: Browser 使用 4178 普通管理员角色 mock 验证：账号新建和保存可用；不分佣账号保存可用；手动补拉可用；商品口径保存可用。相同角色下，线索中心维护已禁用，线索分配试运行只读。`App.tsx` 只对后台入口做 `admin` 角色门禁，各子页并未统一接收最高管理员权限
- **是否原型 / mock 态**: 是；mock 只替换当前用户身份，控件可用/禁用由真实页面代码决定，因此可作为权限交互证据
- **现状**: 普通管理员在部分后台页仍拥有写入口，权限表现不一致
- **预期**: 按已确认方向，由 `DYDATA-32` 建立最高管理员可配置的角色权限；在该改造完成前，普通管理员目标为只读
- **修改建议**: 不在 PAGE_EXPLAINER 中定义字段级权限矩阵。由 `DYDATA-32` 统一权限源，并让各后台写按钮、表单和对应提交行为消费同一权限判断；完成后回跑普通管理员角色验收
- **解决记录**: none

### GAP-P3-02: 线索分配规则和总部池闭环尚未由专项 BRD 冻结

- **分类**: `out_of_scope`
- **所在页面**: 线索分配后台 (`/admin/clue-allocation/rules`、`/trial`、`/records`、`/headquarters`)
- **所在模块**: 固定分配策略、试运行/重建、总部线索池
- **所在元素**: 规则参数、版本发布、试运行预览与执行、总部池筛选及后续处置
- **证据来源**: Browser 已验证四个子视图和当前控件；`explainer-flow-dy-data.md` 仅锁定导航；用户已明确新分配规则、总部池流转和旧引擎退役由 `DYDATA-36` 线索中心 BRD V1.0 固化
- **是否原型 / mock 态**: 是；4175 展示演示规则、试运行和总部池记录，能证明页面交互结构，但不能证明最终生产业务规则
- **现状**: 页面已经能创建/查看规则版本、预览和执行试运行、查看记录及总部池库存，但评分、轮次、关闭入池、再投放等业务含义仍在专项 BRD 范围内
- **预期**: `DYDATA-36` 冻结线索池、跟进池、总部池、轮次、SLA、保护期、分配评分和总部池闭环后，再把相关 Phase 3 语义改为最终业务表述
- **修改建议**: 当前页面可见交互结构已由需求方确认并标记为 `locked`，但分配业务语义仍以本差异项和 `DYDATA-36` 为边界；不从 mock 数据反推最终分配规则
- **解决记录**: none

### GAP-P3-03: DYDATA-19 新结算与财务路由尚未形成可独立访问的页面闭环

- **分类**: `resolved`
- **所在页面**: DYDATA-19 财务流程原型（当前所有视图共用 `/`）
- **所在模块**: 门店结算、发票确认、管理员财务导航与订单穿透
- **所在元素**: 门店端和财务端角色切换、侧栏二级入口、订单明细入口
- **证据来源**: Playwright 于 2026-08-20 打开 `http://127.0.0.1:4319/`，完成门店端、财务端、推广服务费、管理服务费及导入弹窗点击；所有视图 URL 始终为 `/`。DYDATA-19 已确认规格要求 `/settlement`、`/settlement/invoice`、`/finance/promotion`、`/finance/management`、两个订单费用子页、`/finance/stores`、`/finance/disputes`、`/finance/imports`
- **是否原型 / mock 态**: 是；本差距针对原型无法表达已确认的跨页路由和返回关系，不把未接后端视为缺陷
- **现状**: 通过组件内状态切换视图，刷新、复制地址、浏览器返回和深链无法表达具体业务页面
- **预期**: 每个已确认页面都有稳定路由；列表到订单子页、门店账单到开票确认、业务页到只读导入记录均能往返并保留筛选上下文
- **修改建议**: 在独立原型内补齐路由语义与返回路径，继续使用合成数据，不连接真实 API
- **解决记录**: 2026-08-20 loop 1 已使用 History API 补齐稳定路由；Playwright 直接打开 `/finance/promotion`，点击管理服务费后 URL 更新为 `/finance/management`，订单明细双子路由由自动化测试覆盖。

### GAP-P3-04: 财务指标未表达单月与累计双口径

- **分类**: `resolved`
- **所在页面**: 推广服务费、管理服务费
- **所在模块**: 顶部金额指标与筛选
- **所在元素**: 推广费总额、已确认金额、已开票金额、已结算金额、审核未通过金额；管理费总额、已确认金额、待开票金额、已开票金额
- **证据来源**: Playwright 于 2026-08-20 验证两页只显示单组金额卡片和账期筛选，没有“单月 / 累计”切换。DYDATA-19 已确认：已确认金额只显示单月；账单总额、待开票金额、已开票金额及推广费结算结果提供单月与自 2026 年 8 月起累计口径
- **是否原型 / mock 态**: 是；差距针对口径切换和累计起算说明的页面表达，不要求原型实现生产聚合
- **现状**: 用户无法判断卡片是单月还是累计，也无法验证累计口径不包含 2026 年 7 月演示数据
- **预期**: 页面默认单月，可切换累计；已确认金额始终标识为单月；累计口径明确从 2026 年 8 月起，并与列表、汇总、导出筛选保持一致
- **修改建议**: 增加视图口径切换、卡片口径标签和累计起算说明，提供可点击的合成数据状态
- **解决记录**: 2026-08-20 loop 1 已增加“单月 / 累计”切换、已确认金额仅单月标签和累计起算说明；Playwright 已点击累计并保存截图。

### GAP-P3-05: 推广费状态链与系统边界文案不完整

- **分类**: `resolved`
- **所在页面**: 门店开票确认、管理员推广服务费
- **所在模块**: 月度节奏、状态筛选、状态标签和驳回后操作
- **所在元素**: 发票状态枚举及“厂端审核”流程说明
- **证据来源**: Playwright 于 2026-08-20 验证管理员推广费筛选仅有“提交成功，待厂端审核 / 审核通过，已结算 / 审核不通过”，页面月度节奏仍把“厂端审核”作为系统流程节点。DYDATA-19 已确认完整状态为“待开票 / 提交成功，待厂端审核 / 审核通过，已结算 / 审核不通过，请重新上传”，且系统不创建审核任务，管理员导入的是系统外已完成结果
- **是否原型 / mock 态**: 是；差距针对可见文案与状态语义冲突，不要求原型执行真实审核
- **现状**: 缺少待开票状态及重新上传指引，流程图容易让用户理解为系统内存在厂端审核节点
- **预期**: 状态链完整；明确“系统外审核、管理员导入结果、系统内不再审核”；审核不通过时从原记录进入重新登记并保留历史
- **修改建议**: 更新状态枚举、筛选、时间线和驳回详情/重新登记入口，保留原型边界提示
- **解决记录**: 2026-08-20 loop 1 已补齐四态筛选和“系统外审核 / 管理员导入已完成结果 / 系统内不创建待审核任务”文案；浏览器快照已验证。

### GAP-P3-06: 导入差异、更正、全错行与并发冲突缺少可走通反馈

- **分类**: `resolved`
- **所在页面**: 四类业务导入入口、导入记录、管理服务费单店修改、账单异议处理
- **所在模块**: 导入预检、差异确认、失败结果、版本覆盖和冲突反馈
- **所在元素**: “模拟校验并导入”按钮、导入记录、错误下载、刷新最新数据
- **证据来源**: Playwright 于 2026-08-20 打开管理服务费导入弹窗并点击模拟导入，页面只返回“模拟导入成功”，没有无变化、差异覆盖、全部错误行、分页/下载、更正版本或多人并发冲突状态。DYDATA-19 已确认四类导入必须整批校验、返回全部错误行、支持幂等无变化与差异新版本，并统一展示旧版本冲突和刷新入口
- **是否原型 / mock 态**: 是；差距要求原型表达用户可见的关键状态，不要求保存原文件或实现真实并发
- **现状**: 只有成功路径，无法评审高风险数据写入和多人竞争的页面闭环
- **预期**: 至少可切换首次成功、无变化、差异待确认、整批失败、已更正和版本冲突；失败态显示全部错误行摘要、分页和下载入口；冲突态显示读取版本、当前版本、最近操作人/时间及刷新动作
- **修改建议**: 用场景切换和合成数据补齐关键结果页、版本历史抽屉与冲突提示，并让导入记录只读承接业务页发起的任务
- **解决记录**: 2026-08-20 loop 1 已补齐首次成功、无变化、差异待确认、整批失败和版本冲突五种场景；Playwright 已验证全错行下载与读取版本/当前版本冲突反馈，控制台 0 错误、0 警告。
