## 产品背景与定位

### 产品是什么

线索中心把抖音线索转化为内部可经营、可分配、可跟进和可审计的促核销任务，并以完整线索主池保留订单的全生命周期证据。系统不沿用抖音跟进归属作为内部责任，而是依据已发布规则、门店资格和能力评分形成唯一当前责任门店。门店在明确的首次跟进 SLA 或核销保护期内处理当前有效轮次，总部通过经营指标、分配记录和总部池持续治理。产品最终以同口径总体核销率是否高于 2026 年 1 至 6 月基线判断业务价值，而不是以点击量或轮次数替代结果。

### 使用者

| 使用者 | 使用场景 |
|--------|---------|
| **总部业务侧与总部运营** | 统一业务口径，查看完整主池、经营结果、分配运行和总部池库存，识别数据或候选覆盖问题。 |
| **最高管理员** | 配置并发布规则版本，执行试运行、受控重建和高风险治理操作，查看完整审计证据。 |
| **普通管理员** | 只读查看规则、运行状态、分配记录和总部池，协助定位异常但不代替门店操作。 |
| **区域或多店管理人员** | 在授权范围内监督门店线索库存、跟进行为和核销表现，不因管理可见而获得完整联系方式。 |
| **门店客服或抖音负责人** | 处理当前分配给本店的有效线索，查看授权联系方式并登记本轮跟进结果。 |

## 区块详情

### ① 视图导航与范围筛选

**所属页面**：线索中心（路由: /clues、/clues/details）

**布局**：

```
┌──────────────────────────────────────────────────────────────┐
│ [线索看板] [线索明细]                                        │
├──────────────────────────────────────────────────────────────┤
│ [省份*] [城市*] [门店*] [日期起] [日期止] [状态] [商品类型]   │
│                                                [清空筛选]     │
└──────────────────────────────────────────────────────────────┘
* 单店账号隐藏组织筛选，多店和管理账号按授权范围显示。
```

**业务逻辑**：
- 看板和明细共用可表达的筛选条件，切换视图时保留条件；修改条件后从第一页重新读取。
- 单店账号只筛选线索生成日期、线索状态和商品类型；多店及管理账号增加省份、城市和门店筛选，候选值不得超出账号数据范围。
- 起止日期均按用户选择的自然日整日计算，结束日期包含当日全部数据。
- 线索状态候选与店端显示状态一致，只使用待跟进、已跟进、超期失效、主动战败、已核销和已退款。
- 清空筛选恢复当前账号的默认数据范围，不扩大权限，也不保留隐藏条件。

**涉及使用者**：总部业务侧与总部运营、普通管理员、区域或多店管理人员、门店客服或抖音负责人

### ② 经营指标看板

**所属页面**：线索中心（路由: /clues）

**布局**：

```
┌──────────┬──────────┬──────────┬──────────┐
│ 主池规模 │ 门店库存 │ 总部库存 │ 跟进表现 │
├──────────┼──────────┼──────────┼──────────┤
│  核销数  │总体核销率│成熟状态  │门店表现  │
└──────────┴──────────┴──────────┴──────────┘
```

**业务逻辑**：
- 完整主池规模、核销数和总体核销率按唯一订单去重，不能因同一订单存在多条原始记录、多轮分配或多次跟进而重复计算。
- 总体核销率按下单时间所属自然月归属，包含首次采集时已经核销或退款的订单，并标明 30 天成熟窗口内的“观察中”和期满后的“已成熟”。
- 门店跟进池库存、总部池库存、线索跟进率和保护期到期情况分别展示，池位置、订单状态和轮次状态不得混为一个指标。
- 门店指标只统计正式分配给对应门店的轮次和订单，总部池及试运行结果不进入任何门店分母。
- 总部可比较 2026 年 1 至 6 月基线、过渡月和上线后成熟周期；门店及区域角色仅查看授权范围内的指标。

**涉及使用者**：总部业务侧与总部运营、普通管理员、区域或多店管理人员、门店客服或抖音负责人

### ③ 线索明细与导出

**所属页面**：线索中心（路由: /clues/details）

**布局**：

```
┌──────────────────────────────────────────────────────────────┐
│ 当前筛选结果                              [总数] [导出]       │
├──────────────────────────────────────────────────────────────┤
│ 联系方式 | 线索状态 | 分配轮次 | 本轮跟进时间 | 商品与时间   │
│                         行点击/双击进入详情                   │
├──────────────────────────────────────────────────────────────┤
│ 移动端任务卡片                           [查看详情]           │
├──────────────────────────────────────────────────────────────┤
│ [每页数量] [首页] [上一页] [页码] [下一页] [末页]            │
└──────────────────────────────────────────────────────────────┘
```

**业务逻辑**：
- 主列表按联系方式、线索状态、分配轮次、本轮跟进时间、商品名称、商品类型、线索生成时间和本轮失效时间呈现门店任务。
- 分配轮次 ID 等内部技术编号不作为店端主信息；详情通过稳定订单和当前行上下文定位。
- 桌面端支持点击“查看详情”或双击指定行区域打开详情，移动端以任务卡片保留同等业务信息和明确详情入口。
- 导出覆盖当前账号可见范围内、符合当前筛选的全部结果，不受当前分页限制；每条联系方式仍按该账号对该线索的联系方式操作权决定是否输出完整号码。
- 无结果时展示空状态并禁用导出；导出、翻页或详情读取失败时留在当前页面给出可恢复反馈。

**涉及使用者**：总部业务侧与总部运营、区域或多店管理人员、门店客服或抖音负责人

### ④ 联系方式与订单摘要

**所属页面**：线索中心（路由: /clues/details）

**布局**：

```
┌──────────────────────────────────────┬───────────────────────┐
│ 联系方式  138****5678  [查看] [复制] │ 线索状态              │
├──────────────────────────────────────┴───────────────────────┤
│ 商品与订单：订单编号 / 商品名称 / 商品类型 / 订单状态        │
│             下单时间 / 核销状态                              │
└──────────────────────────────────────────────────────────────┘
```

**业务逻辑**：
- 联系方式默认展示中间四位脱敏手机号；只有当前有效轮次所属门店的获授权用户可以按次查看或复制完整手机号。
- 查看和复制完整手机号均属于敏感操作并需要留痕；复制必须写入完整号码，不能复制脱敏字符串后提示成功。
- 轮次失效、订单已核销或已退款、账号不是当前责任门店，均只显示脱敏手机号和“已失效不可跟进”等明确原因。
- 摘要展示订单编号、完整商品名称、商品类型、订单状态、下单时间和核销状态；下单时间不得用线索生成时间或分配时间替代。
- 不展示抖音跟进归属作为内部责任门店，当前责任只由自有分配轮次确定。

**涉及使用者**：门店客服或抖音负责人、区域或多店管理人员、总部业务侧与总部运营

### ⑤ 当前有效轮次跟进操作

**所属页面**：线索中心（路由: /clues/details）

**布局**：

```
┌──────────────────────────────┐
│ 跟进结果                     │
│ ( ) 已预约                   │
│ ( ) 待进一步跟进             │
│ ( ) 线索战败                 │
│ ( ) 未联系上                 │
│ ( ) 客户要求换门店           │
│ [本次跟进结论/备注          ]│
│ [保存本次跟进]               │
└──────────────────────────────┘
```

**业务逻辑**：
- 只有当前有效轮次所属门店的获授权用户可提交跟进；历史轮次、超期、战败、已核销和已退款线索整块不可编辑并说明原因。
- 跟进结果固定为已预约、待进一步跟进、暂不需要（线索战败）、未联系上和客户要求换门店，可同时填写本次结论或备注。
- 已预约、待进一步跟进和未联系上均算已产生跟进，并由本轮首次保护型动作启动一次核销保护期；后续动作不重新计时。
- 暂不需要和客户要求换门店会立即关闭当前轮次，并从下一个启用策略继续分配；原门店进入历史排除。
- 订单核销或退款优先于跟进动作、首次跟进 SLA 和保护期，终态确认后不能继续保存跟进。

**涉及使用者**：门店客服或抖音负责人

### ⑥ 分配轮次与跟进历史

**所属页面**：线索中心（路由: /clues/details）

**布局**：

```
┌──────────────────────────────────────────────────────────────┐
│ 线索跟进历史                                      2轮·3记录 │
├──────────────────────────────────────────────────────────────┤
│ 第1轮 · 销售店优先 [超期失效]                              │
│ 分配时间 | 跟进门店 | 失效原因 | 失效时间 | 最近结果        │
│   跟进时间 | 跟进动作 | 备注                         [删除*] │
├──────────────────────────────────────────────────────────────┤
│ 第2轮 · 15公里城市优选 / 当前 [待跟进]                      │
│ 分配时间 | 跟进门店 | 再分配原因 | 最近结果                 │
├──────────────────────────────────────────────────────────────┤
│ [上一条线索]                    当前页位置      [下一条线索]  │
└──────────────────────────────────────────────────────────────┘
* 仅最高管理员可见。
```

**业务逻辑**：
- 只有真实选中门店时才形成分配轮次，轮次从 1 连续编号；被禁用或无候选的策略只记录跳过原因，不生成空轮次。
- 每轮显示“第 N 轮 · 分配策略名”、分配时间、真实跟进门店、再分配原因、失效时间、最近结果和该轮全部跟进记录。
- 历史记录和当时的策略、评分及责任关系不可被后续规则或评分变化改写。
- 最高管理员可通过垃圾桶图标删除尚未删除的跟进记录，删除需要二次确认并保留操作者、时间和结果审计；其他角色只读。
- 桌面端可在浮层底部切换上一条或下一条线索；移动端可水平滑动切换，切换时清除上一条线索的完整号码和未提交草稿。

**涉及使用者**：门店客服或抖音负责人、区域或多店管理人员、总部业务侧与总部运营、最高管理员

### ⑦ 线索采集状态与配置

**所属页面**：数据同步（路由: /admin/sync、/sync-admin）

**布局**：

```
┌──────────────────────────────────────────────────────────────┐
│ 运行摘要：任务数 / 当前任务 / 自动采集 / 同步间隔           │
├──────────────────────────────────────────────────────────────┤
│ 后台采集状态：进度 / 最近成功 / 最近失败 / 当前范围          │
├──────────────────────────────────────────────────────────────┤
│ 自动采集配置：启停 / 历史回填 / 滚动回看 / 间隔   [保存]     │
├──────────────────────────────────────────────────────────────┤
│ 最近任务日志                                      [刷新]     │
└──────────────────────────────────────────────────────────────┘
```

**业务逻辑**：
- 页面明确展示线索自动采集是否启用、当前是否运行、处理范围、最近成功或失败及任务日志，便于判断“是否在跑、跑到哪里、为何失败”。
- 历史回填和日常滚动采集分开配置；日常采集需覆盖最近可能发生订单状态变化的时间范围，并避免抓取平台尚未稳定返回的最新时段。
- 只有具备配置写权限的角色可以保存采集节奏，普通管理员默认只读；草稿与服务器配置不一致时必须明确提示。
- 配置和日志不得展示应用密钥、访问令牌、完整手机号或其他不必要的敏感信息。
- 无运行任务、无失败记录或无日志时分别展示可理解的零值与空状态，不把空状态误报为运行异常。

**涉及使用者**：最高管理员、普通管理员、开发测试运维人员

**业务逻辑**：

- 执行失败时保留已完成范围和失败原因，允许按明确范围恢复，不以整页跳转或无反馈结束操作。

**涉及使用者**：最高管理员、普通管理员、开发测试运维人员

### ⑨ 分配规则与版本

**所属页面**：线索分配后台（路由: /admin/clue-allocation/rules）

**布局**：

```
┌──────────────────────────────┬───────────────────────────────┐
│ 规则范围与已发布版本         │ 新建规则 / 新建草案版本       │
│ 作用范围 / 状态 / 生效参数   │ 时限 / 保护期 / 评分参数      │
│ 固定策略模块及执行顺序       │ 策略启停 / 顺序 / 配置半径    │
│ [发布] [退役]                │ [保存草案]                    │
└──────────────────────────────┴───────────────────────────────┘
```

**业务逻辑**：
- 规则作用范围支持锚点门店、门店组、城市和全局，命中优先级固定为锚点门店、门店组、城市、全局。
- 固定策略模块只包括销售店优先、城市半径优选和城市兜底；模块类型固定，但允许启停、调整执行顺序和配置半径等参数。
- 规则版本使用草稿、已发布和已退役生命周期；草稿可调整，发布后不可修改，只能通过新版本迭代。
- 线索首次进入正式分配时锁定命中的已发布版本，后续轮转继续沿用，不因后台发布新版本而切换。
- 版本同时定义首次跟进 SLA、核销保护期、评分权重、观察窗口和冷启动参数；门店权重当前保持默认值 1。
- 最高管理员可创建、发布和退役，普通管理员只读；所有发布与退役动作必须审计。

**涉及使用者**：最高管理员、普通管理员、总部业务侧

### ⑩ 分配试运行与受控重建

**所属页面**：线索分配后台（路由: /admin/clue-allocation/trial）

**布局**：

```
┌──────────────────────────────────────────────────────────────┐
│ 待试运行线索：[选择] [全选当前页] [清空] [预览] [启动]      │
├──────────────────────────────────────────────────────────────┤
│ 当前预览：分配 / 总部池 / 跳过 / 候选与评分摘要              │
├──────────────────────────────────────────────────────────────┤
│ 来源试运行批次 / 覆盖保护 / 影响摘要       [预览] [重建]    │
└──────────────────────────────────────────────────────────────┘
```

**业务逻辑**：
- 待试运行范围只包含尚无当前有效轮次且满足分配判断条件的活跃线索；总部池线索在 V1 不通过本页再次投放。
- 预览使用目标规则、候选资格和评分快照计算，但不改变池位置、不创建正式轮次，也不授予门店责任。
- 只有预览与当前选择、来源批次及覆盖选项完全一致时才能启动；任一条件变化都使旧预览失效。
- 试运行结果与正式数据集隔离，不进入门店库存、跟进率、核销转化能力或总体效果判断。
- 受控重建以一个明确来源批次为范围，默认阻止覆盖已有正式跟进记录的线索；特权覆盖必须单独确认并审计。
- 普通管理员只读，移动端仅查看；最高管理员在桌面端执行试运行和重建。

**涉及使用者**：最高管理员、普通管理员、总部业务侧与总部运营

**布局**：

### ⑫ 总部线索池

**所属页面**：线索分配后台（路由: /admin/clue-allocation/headquarters）

**布局**：

```
┌──────────────────────────────────────────────────────────────┐
│ 总部线索池                    [当前库存] [筛选结果]           │
├──────────────────────────────────────────────────────────────┤
│ [池状态] [进入原因] [日期起] [日期止] [订单状态] [订单号]    │
│                                               [筛选] [清空]  │
├──────────────────────────────────────────────────────────────┤
│ 订单 / 商品 / 锚点证据 / 入池原因 / 入池时间 / 当前状态      │
├──────────────────────────────────────────────────────────────┤
│ [每页数量] [首页] [上一页] [页码] [下一页] [末页]            │
└──────────────────────────────────────────────────────────────┘
```

**业务逻辑**：
- `follow_poi_id` 缺失、锚点无法映射、锚点地理数据不可用、全部启用策略无候选或末轮结束的活跃线索进入总部池，并保留标准入池原因。
- 总部池库存按唯一活跃订单去重；已核销或已退款线索关闭后不再计入当前库存，试运行结果不进入总部池。
- 页面支持按总部池状态、入池原因、进入自然日、订单状态和订单号筛选，并展示当前库存、筛选结果和分页。
- 总部池不属于任何门店，不进入门店线索数、跟进率或核销转化能力分母；管理可见不自动授予完整手机号。
- V1 仅提供库存查看和原因治理，不提供总部池再次进入门店跟进池的操作。

**涉及使用者**：总部业务侧与总部运营、最高管理员、普通管理员
