## 产品背景与定位

### 产品是什么

抖音经营引擎把销售、核销、商品、费率、退款、月度账单、方向确认、异议、发票登记和财务结果导入组织成可复核的结算闭环。门店账号负责确认账单、提交异议和登记推广服务费发票；财务人员使用管理员角色导入系统外审核结果及管理服务费明细。系统提供登记、状态回传、查询、导出和审计，不创建开票申请单、不执行真实开票或资金划拨。

### 使用者

| 使用者 | 使用场景 |
|---|---|
| **门店账号** | 查看本店账单和订单依据，按费用方向确认、提交异议、登记推广服务费发票并查询状态。 |
| **管理员（含财务人员）** | 查询推广费和管理服务费，处理异议，导入系统外审核/结算结果与管理服务费发票明细。 |
| **最高管理员** | 在本模块拥有与管理员一致的业务操作能力；仍受统一页面权限和门店范围校验。 |
| **总部运营人员** | 查看全国门店月度或正式累计排名，不因此获得其他门店财务明细权限。 |

## 区块详情

### ① 排名筛选与结果

**所属页面**：全国门店榜单（路由: /ranking）

**布局**：

```
[月度/累计][月份][产品][门店][排名依据] [指标卡] [排名表]
```

**业务逻辑**：
- 月度仅统计所选月，正式累计从 `2026-08` 起；全国前 20 是只读对标例外。
- 产品筛选同步作用于指标和排名，空结果不沿用旧数据。

**涉及使用者**：总部运营人员

### ② 账单版本、方向确认与订单下钻

**所属页面**：月度账单确认（路由: /settlement）

**布局**：

```
[账期][门店][版本] [双方向指标] [确认/异议/开票入口] [订单下钻]
```

**业务逻辑**：
- 账单新版本替代旧版本但永久保留历史；推广费和管理费分别确认且互不阻断。
- 1—6 日内等待门店确认，6 日后按自动确认规则处理；确认时间取服务器校验通过时间。

**涉及使用者**：门店账号

### ③ 费用方向、筛选与明细

**所属页面**：订单费用明细（路由: /details）

**布局**：

```
[推广费/管理费][筛选][搜索][导出] [一券一方向明细表]
```

**业务逻辑**：
- 两个费用方向始终单选；列表与导出复用同一筛选、权限和口径。
- 原费用和退款调整分别展示，汇总显示调整后净额，不按比例猜测缺失券级映射。

**涉及使用者**：门店账号、管理员

### ④ 发票登记、状态与历史

**所属页面**：推广费发票登记（路由: /settlement/invoice）

**布局**：

```
[门店/账期/账单版本] [20位号码][日期][金额][提交] [四态时间线][历史]
```

**业务逻辑**：
- 门店只登记系统外已开具的推广费发票；系统不创建申请单、不执行开票或发送企业微信。
- 状态固定四态，审核/结算结果由管理员导入；重新上传形成新版本。

**涉及使用者**：门店账号

### ⑤ 指标、发票与订单穿透

**所属页面**：管理员推广服务费（路由: /finance/promotion）

**布局**：

```
[单月/累计][账期/门店/四态] [指标卡] [发票表] [订单穿透]
```

**业务逻辑**：
- 显示账单总额、已确认、待开票、已开票和已结算；已确认金额只按单月。
- 管理员导入的是系统外已完成审核/结算结果，系统内不生成待审核任务。
- 订单穿透使用 `/finance/orders/promotion`，并保持推广服务费方向。

**涉及使用者**：管理员、最高管理员

### ⑥ 指标、扣款与订单穿透

**所属页面**：管理员管理服务费（路由: /finance/management）

**布局**：

```
[单月/累计][账期/门店] [指标卡] [厂家扣款/发票表] [订单穿透]
```

**业务逻辑**：
- 当期导入上一账期管理服务费明细；系统导入时间即审核通过和已结算时间。
- 厂端视角已开票与扣款相同，不套用推广费审核状态链。
- 订单穿透使用 `/finance/orders/management`，并保持管理服务费方向。

**涉及使用者**：管理员、最高管理员

### ⑦ 门店与 SAP 信息查询

**所属页面**：门店基础信息（路由: /finance/stores）

**布局**：

```
[门店搜索/筛选] [门店ID | 门店名称 | SAP展示字段 | 更新时间]
```

**业务逻辑**：
- SAP 信息用于展示和财务核对，所有导入匹配只使用门店 ID。
- 禁止按 SAP 编码、名称、金额或月份模糊匹配。

**涉及使用者**：管理员、最高管理员

### ⑧ 门店提交与管理员处理

**所属页面**：账单异议（路由: /finance/disputes）

**布局**：

```
[筛选][异议列表] [订单/金额/具体原因] [待处理→审核中→待审批→结果]
```

**业务逻辑**：
- 门店提交类型、具体原因、订单、金额、联系人和手机号。
- 内部管理员在系统页面处理；异议不阻断另一费用方向，成立时生成新账单版本。

**涉及使用者**：门店账号、管理员、最高管理员

### ⑨ 四类模板、差异、错误与版本

**所属页面**：财务导入（路由: /finance/imports）

**布局**：

```
[模板类型][账期][上传] [首次/无变化/差异/整批失败/版本冲突] [历史]
```

**业务逻辑**：
- 四类模板统一版本机制；预校验展示全部错误行并提供错误文件，任一错误使正式业务表整批零写入。
- 无变化不生成版本；差异需确认；提交时版本变化返回冲突并要求刷新，不部分写入或进入待匹配池。

**涉及使用者**：管理员、最高管理员
