# DYDATA-104：10月30日参与分佣商品类型增量

本记录覆盖商品分类这一责任子集。开发基线 `9831027a`；用户已在104负责会话授权按新增五项实施。本分支没有执行生产查询、分类应用、费用补算、账单确认或部署，不能作为生产完成证明。

## 已定位原因与实现

1. 旧转换、商品同步及编辑只识别内部 scope 精确为“精诚养车”的 SKU，遗漏其他 scope 的正式分佣商品。新增精确 SKU 的已发布历史分佣规则证据集合，按生效时间和有效正费率判断；商品下架及后续停用不抹掉既有历史资格。名称、Product ID 与相邻 SKU 均不能扩大集合。当前或正式规则快照明确为售后官方的保持官方，其余有证据的目标归为精诚养车。
2. 既有转换入口新增显式 `--participating-skus` 模式，旧 scope 操作保持兼容。预演报告逐 SKU 列出前后类型、官方保留/转换数量、规则版本/日期、缺档和无资格证据组。应用锁定目录与规则表，重新核对完整证据摘要；审计、回读和写入同事务，重放幂等，不排队费用重建。具体命令及保护见[操作流程](../ops/product-type-conversion.md)。
3. 商品同步、分类单改/批改/导入、已生效新正式规则发布维持同一类型口径。参与资格来自正式规则；分类编辑不会改内部 scope、费率或成员资格。目录写入与规则发布按 SKU 行锁串行读取，避免资格查询与同 SKU 并发写入交错。
4. 只改目录不能解决旧费用与保护账单上的类型快照。新增结算分析合同 `commission-product-type-v3`，按正式费用或冻结分录的准确 SKU 建立展示分类，分别重聚合 all 与各类型；同订单多 SKU 不因旧类型合并而重复计订单数。原费用、原规则、账单行/分录、确认及发票不更新。`snapshotProductType` 保留原财务类型；当前展示类型、分佣明细和财务订单导出使用相同精确 SKU 解释。
5. 不隐藏缺证：发布统计按 `commission_type_coverage` 返回已分类、缺 SKU、缺档、未归一目录等原因及事实/SKU数量。无法追到逐条来源的历史聚合保持可见，并返回未覆盖聚合分区行数；这些不是缺券数量。不能据下拉只剩两类便宣称全量修复。
6. 全国月榜、单店分账已经使用结算专属发布元数据。订单分佣明细页原来调用共享 `/meta/filters`，会混入不分佣目录和旧财务类型，现改为读取 settlement 发布的专属维度。财务方向列表与订单页没有商品类型下拉，分别沿用 finance 发布数据及正式订单查询；该查询的展示类型已同步。开票/发票状态页只消费共享门店与月份，没有消费商品类型，不为本次分类引入额外分析依赖。独立打榜筛选、成员 scope 和计算合同不变。

```bash

```

## 集成及生产尚需完成

- 新API字段语义需要在接口定义和 foundation 漂移台账登记：`productType` 为分析展示类别，`snapshotProductType` 为不可变财务原类型。该上游回收由负责集成者完成，本分支不直接改 foundation。
- CI 在真实 PostgreSQL 执行10项新增门禁及现有全量；在实际规模下核验新聚合SQL的时间和资源，不能以SQLite耗时代替生产性能。
