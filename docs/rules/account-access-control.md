# 账号、页面权限与门店范围规则

本文件是账号授权的长期规则。DYDATA-105 于 2026-10-22 覆盖原 DYDATA-32/DYDATA-93 的两类管理员差异；用户确认“管理员可以有账号新增、变更权限，但不能删除；其他可以一致”。本文件与分佣比例、金额算法解耦。

## 1. 角色与能力

业务角色仅为 `admin`（管理员）与 `store`（门店账号）。最高管理员不再作为可创建、可配置或对外返回的独立角色。

| 能力 | 全部门店范围管理员 | 组织或指定门店范围管理员 | 门店账号 |
|---|---|---|---|
| 页面权限 | 固定全部已注册页面 | 固定全部已注册页面 | 角色默认值 + 单账号允许 − 单账号禁止 |
| 账号新增、变更、密码重置 | 可管理全部角色和账号 | 只可管理全部门店均在本人范围内的门店账号 | 不可管理账号 |
| 账号删除 | 不提供 | 不提供 | 不提供 |
| 全局配置写入 | 可执行 | 不可执行，页面解释影响范围 | 不可执行 |
| 业务数据 | 全部门店 | 当前动态组织或指定门店范围 | 指定门店范围 |

`can_manage_accounts` 仅表示管理员可进入账号管理，目标账号仍须服务端校验；`can_manage_global_settings` 仅在管理员且范围为 `all` 时为真。页面固定允许不代表拥有全国数据或全局写入能力。

旧内部 `is_highest_admin` 暂作为全局管理员能力的兼容别名，不作为新角色或前端新判断依据。环境配置账号继续可登录，身份统一为管理员且全部门店范围。

## 2. 账号管理与范围

- 全范围管理员可新增/变更管理员与门店账号，含角色、状态、密码、组织和门店范围。
- 受限管理员不能管理管理员账号。门店账号当前完整范围必须非空且属于操作者当前授权集合；只与其中一家门店重叠不构成管理授权。
- 对受限管理员，新增或调整后的目标只能是门店账号，拟分配全部门店必须属于本人范围。不能通过编辑、密码重置、页面差异、恢复默认、批量导入或直接调用 API 绕过。
- 账号列表、未激活门店、目录、导入模板/预览及变更记录均按同一管理边界过滤；越权账号与不存在账号不作存在性区分。
- 所有账号均不提供物理删除接口或按钮。停用是可审计的状态变更，不删除历史关联。不得停用自己。
- 至少保留一名已初始化、启用、有密码且范围为全部门店的数据库管理员。停用、降为门店或收缩最后一名的范围必须拒绝。影响该集合的账号写入使用事务锁，并在获得锁后重新检查操作者、目标、范围和剩余数量；不能以环境账号代替此持久账号保护。

## 3. 全局写入

只有全部门店范围管理员可以修改全局 SKU 费率、商品口径、费率导入、结算范围版本、不分佣归属账号例外、角色默认值、数据同步配置/触发与全局结算重算。

- 受限管理员仍可进入对应页面读取允许展示的配置与结果；前端禁用全局写按钮并解释会影响本人范围外的数据，后端独立拒绝。
- 单条费率发布与文件导入正式提交仍遵守不可变版本、日期/比例校验、幂等、事务、审计及锁账保护。手工多选逐条发布，文件导入整批原子提交。
- 发布成功后的受控重算仍在原事务内入队。手工入口统一称为“重新计算结算结果”，不表示补采、账单确认、开票或付款。
- 错误反馈区分权限、日期冲突、幂等键复用、批次状态、校验与页面回读失败，不把所有 403 解释为非最高管理员。

## 4. 页面权限

管理员固定拥有全部活跃页面，包括 D02 账号管理与 D10 数据同步；角色默认值和单账号 overrides 均不得限制或单独调整管理员页面权限。

门店账号继续采用：

```text
有效页面 = 角色默认页面 + 单账号额外允许 - 单账号额外禁止
```

- 门店角色默认值由全范围管理员调整，修改前预览并确认继承账号影响数量。
- 继承账号使用新默认值；有自定义差异的门店账号保持原有效页面，重新计算相对差异。可对单账号恢复默认，不批量重置所有自定义账号。
- A03 抖音打榜为所有有效登录账号固定允许，deny 不改变此例外；三个排行及导出使用全量组织数据，原始证据和其他业务明细不随之开放。
- D10 不向门店账号开放。只授予门店账号后台页面不授予管理员写权限。
- 页面由 `access_control.PAGE_DEFINITIONS` 登记；前端菜单、路由、API和导出使用同一有效结果。未登记业务 API 默认拒绝。新增页面自动对管理员开放，门店角色须明确授权。
- 登录、激活、忘记密码和个人密码修改属于通用账号能力，不进入页面矩阵。

## 5. 组织与门店数据范围

范围显式为 `all`、`specified` 或 `none`。空门店集合绝不解释为全部门店。管理员也不得由角色自动扩大全部门店范围。

- 管理员可绑定集团、服务中心、大区、区域或指定多门店。集团只需集团名；服务中心只需服务中心名；大区需服务中心+大区；区域需服务中心+大区+区域。服务层级不按集团过滤。
- `org_scope` 必须配合 specified；每次请求按正式组织版本和有效门店动态解析。非法或空匹配没有业务数据权限，同名区域按完整路径隔离。
- 使用当前已生效的完整正式 `ranking_store_org_history` 版本，通过系统门店ID关联有效门店；未来版本不提前生效，移出正式名单的门店不沿用历史授权。只有从未发布正式名单时兼容旧组织表。
- 查询、统计、下钻、导出和门店选择器使用同一服务端门店范围。包含门店数据的页面同时校验页面和范围；客户端传入门店ID不构成授权。
- 门店账号保持多门店绑定。结算全国榜对受限账号不开放全局前20；A03 的既有全量例外单独保留。
- 选择器按名称/部分ID搜索，保留跨搜索多选。门店导入支持 xlsx/csv/txt，ID保留前导零，重复去重；未知、越权、名称不符按行拒绝，错误修复前不能应用。

## 6. 新建、激活与批量开通

- 后台手工创建须设置密码，选择至少一个门店或有效管理员范围；保存后可登录。后台已初始化的门店再自助激活时提示已激活。
- 自助激活仍使用所属账户ID和POI ID同记录核验，自动创建/初始化门店账号并绑定唯一核验门店；激活时不能自行选择额外门店。多门店调整由有权限的管理员完成。
- “未激活门店”不是空范围账号。缺失范围的旧门店账号保持 none，不自动提权。
- 批量开通每批最多200个账号，全范围管理员支持管理员、组织账号和门店账号；受限管理员的模板只提供门店账号及本人范围门店，预览和提交均拒绝管理员/越权行。
- 预览不创建账号；提交重新检查文件摘要、唯一标识、操作者当前状态和当前范围。任一错误整批不创建，不覆盖已有账号，范围字段矛盾不得默默放宽。
- 批量初始密码仍按 2026-09-15 确认为 `123456`，用户在个人设置自行修改；已有账号密码不变。数据库仅保存哈希。含初始密码的开通结果响应 no-store，审计不得记录密码。

## 7. 迁移、会话与审计

- 0064 将旧 highest_admin/admin（及遗留 viewer）统一为 admin；保留密码哈希、启用状态、组织绑定、手工门店关系和 store_scope_mode，异常受限的旧最高管理员也不强制改为 all。
- 迁移将旧角色和管理员页面 overrides 的原始信息保存在迁移审计中，再清除管理员运行时差异；门店默认值/差异及历史审计保留。
- 迁移递增 `auth_version` 和 `auth_generation`。旧 Web cookie、CLI/MCP 凭据不能继续使用旧授权；之后每次请求重新读取当前身份与范围。
- 账号角色、状态、范围、密码和权限变化立即生效：Web在下次请求校验版本；CLI/MCP按当前授权代次验证。组织名单变更通过动态范围读取生效，不复用过期门店快照。
- 迁移只在授权环境执行；含账号迁移历史时禁止自动有损 downgrade，须审阅迁移前快照并通过备份恢复。0059对组织账号有损降级的保护继续有效。
- 记录创建/停用/角色/范围、门店默认值、单账号差异及恢复、密码重置事件。记录操作者、操作时角色、时间、对象、前后状态、结果，不记录密码、token或cookie。
- 全范围管理员查看全部权限变更历史；受限管理员仅查看当前可管理门店账号且历史快照也在本人范围内的记录。门店账号不可查看。记录长期保留，不允许业务账号修改或删除。
