# 统一看板发布契约

状态：2026-10-19 用户已确认方向与开发；实现中，尚未部署。

## 用户确认的行为

| ID | 契约 |
|---|---|
| PUB-01 | 所有经营榜单和分析看板只读已发布静态数据；打开页面、筛选、排序、分页及导出不触发业务重算。 |
| PUB-02 | 后台按五分钟调度；导入完成尽早处理变更；无变化可复用；首次构建、更新中、失败和过期状态明确。 |
| PUB-03 | 同页指标、趋势、列表、筛选元数据和导出固定同一版本；构建失败继续读上一完整版本。 |
| PUB-04 | 统一显示数据截至时间与结果更新时间；HTTP 响应时间不冒充数据更新。模块版本不同则展示各自时间。 |
| PUB-05 | 常用首屏和筛选以秒内为验收目标；后台解释业务事实，读取阶段仅做索引筛选和轻量聚合。 |
| PUB-06 | 全年是所选年度，默认当年；全部历史独立选择。账单正式累计起点及操作搜索范围保持原契约。 |
| PUB-07 | 普通发布保留最近两版；关键版本显式 pin，清理保护 active 和读取中的版本。账单、发票及评分证据不受此轮换影响。 |

## 模块边界

纳入：抖音指标榜单、核销表现、线索概览、门店业绩榜单、结算经营读数、财务经营汇总。分配评分保留自身不可变快照并统一显示时间。

线索明细跟进、账单确认/争议、发票登记/生命周期、财务工作队列、采集运行状态、配置计数继续即时读取。混合页面分开表达分析版本和当前操作状态，不能冻结写入资格或授权。

FIN04 门店基础资料与 SAP 异议页属于实时工作队列；其编码、确认状态、更正详情金额和基础资料导出继续读取当前业务状态。本契约中的财务分析指财务经营汇总及费用分析，不能据此声称所有财务 GET 均已静态化。

## 发布与读取协议

- 独立 publication sidecar；不改结算 generation 协议，不删除其 lineage。
- 每个模块拥有不可变发布头及窄分析事实。源数据业务解释、归属判定、核销取消和跟进指标评价只在后台执行。
- `meta.publication`：`id`、`module`、`dataAsOf`、`publishedAt`、`status`、`nextRefreshAt`；允许 `dataAsOf=null` 并明确未知，不能伪造来源覆盖时间。
- 请求可传 `publication_id`。未指定读取最新完整版本；指定版本不可用返回明确过期状态，不能悄悄换成另一版本。缺少首次发布不在 GET 中构建。
- 同页查询锁定版本；取新版本是只读刷新操作。服务端按当前权限重新过滤，版本号不是授权。
- 同一 SQLAlchemy session 完成构建，成功标志与 active 指针同事务提交；失败回滚，旧版继续可读。读取保护保持到结果物化完成。
- 时间筛选使用上海时区。不可将每日 distinct 或分位相加；任意区间依据冻结轮次、券事实及组织有效历史筛选聚合。
- 核销表现冻结窄券字段；榜单冻结订单归属、全部责任轮次的跟进/有效核销判定、历史组织及名单；禁止复制原始响应 JSON。
- 打榜发布在构建事务内对固定五张窄投影表准备 PostgreSQL 统计信息，再交由生命周期切换 active；不能等用户首读触发自动分析。该步骤不分析源业务表，也不单独提交；失败按构建失败处理。
- 财务不可变账单与 generation 可作为后台来源；不得仅引用仍可变化的 legacy-root 并称已冻结。

## 实现模块接口

`apps/api/dy_api/dashboard_publications/schema.py` 提供共享 `metadata`、`runs`、`heads`。各分析模块在同一 metadata 注册自己的表，以 `publication_id` 外键引用 `dashboard_publication_runs.id`，级联仅删除分析投影。

各模块提供 `build(session, publication_id, cutoff)`：批量构建，返回含行数/来源时间的统计字典，不 commit、不切换 active。读取函数接受同一个 session 和已解析 publication ID，返回现有 API data 形状；不读原始业务数据、不写数据、不调用 builder。主代理集成路由与统一错误/元数据。

发布管理负责互斥、完整阶段判断、事务边界、状态、版本解析、保留和 worker 调度；不得为每个筛选组合创建副本。

## HTTP 与运行边界

模块标识为 `douyin-ranking`、`sales`、`clue-overview`、`settlement`、`finance`。
统一筛选元数据入口为 `GET /api/v1/dashboard/publications/{module}/filters`，同样接受 `publication_id`。
既有分析路由保持 data 字段形状，在 `meta.publication` 返回版本信息；文件导出使用 `X-Publication-ID` 标明版本。
管理费更正的当前记录使用 `GET /api/v1/admin/finance/management-invoices/{store_id}/{statement_month}/current` 实时读取，返回既有更正成功响应的记录形状。它执行 FIN02、管理员及当前门店范围检查，不产生分析版本。提交仍执行实时版本校验；409 后由用户显式重新读取当前记录，不能自动覆盖或重复提交更正。
管理费分析行只提供门店和月份定位；是否存在可更正记录由实时 GET 判断，不能依赖冻结行的发票 ID 或 current 标志。读取、提交或同页分析请求明确返回 401/403 后，清除已打开的更正表单并使在途响应失效；409 和普通暂时失败仍保留用户输入。

| 状态 | HTTP | 行为 |
|---|---|---|
| 首次尚未发布 | 503 / PUBLICATION_NOT_READY | 显示准备状态，GET 不执行构建 |
| 指定版本不存在或已清理 | 410 / PUBLICATION_EXPIRED | 客户端最多一次显式读取最新完整版本 |
| 筛选格式错误 | 422 | 显示错误，不循环重试 |
| 数据库读取暂不可用 | 503 | 不泄露 SQL/参数，同查询保留上次完整显示 |
| 更新中或后台失败 | 200 + refreshing/failed | 上一完整版本仍然可用 |
| 账号权限变化 | 401/403 或当前范围过滤 | 清除无权旧行，版本号不能绕过授权 |

`publication-worker` 独立于 API 和采集进程，默认 768 MiB、0.5 CPU、并发 1。
监督进程每 15 秒检查来源变化，正常刷新目标五分钟；单模块子进程默认墙钟限时 180 秒、SQL 限时 120 秒。
来源无变化时只推进下次检查时间，不复制投影；打榜的时间窗口变化需要周期更新。
组织有效版本和上海自然月份是显式时间依赖；跨越边界会触发必要发布，不能仅靠来源表写入计数判断。中断构建在拿到模块锁后恢复为失败，来源忙时也不得永久停留在更新中。
构建使用一致性事务、模块互斥和已知业务写入锁/任务状态保护，不能证明未纳入协议的外部写入或失败采集残留具有完整覆盖。

部署顺序为迁移、五模块逐一限时预热、发布服务就绪、API 切换。预热失败保留旧 API。
发布记录与投影只写 sidecar；数据库迁移本身不复制来源事实。
当前上游不能提供可证明的完整覆盖水位，因此 `dataAsOf` 为 null；界面与导出分别显示来源时间未知、真实结果发布时间。

## 财务账期未完成时的保护

暂缓历史退款恢复不代表账期金额已经完整。settlement 与 finance 构建时，在既有 dimensions JSON sidecar 冻结正式起点（2026-08）至当前上海月的采集完整性；使用每日任务最新拥有代际和 finalize 成功判定。当前未结束月保持未就绪；完整月份没有费用结果仍允许展示真实零。这个状态不等于退款经济口径已核实，也不生成或修改账单。

未就绪或缺少该冻结元数据时，金额读取及导出返回 `503 / PUBLICATION_PERIOD_NOT_READY`，中文消息标明账期；不返回正常零、不使用 410 恢复。财务 MONTH 检查所选月，CUMULATIVE 检查正式起点到所选月；门店榜单的混合月/累计卡片及单店分账含累计，因此检查完整前缀。筛选接口仍返回月份及 `periodReadiness`，供切换可用账期。已冻结状态不会因实时任务变化漂移，后续完成日会通过财务来源指纹触发新版本。GET 只查 sidecar，不读任务表或重算。

## 验证要求

至少覆盖跨月多券、多轮次责任、撤销核销、历史组织变更、同页/导出版本一致、更新期间旧版可用、失败回滚、授权变化即时生效及版本清理并发。使用真实 PostgreSQL 验证事务/索引/性能，浏览器测时验证最终体验。
