# DYDATA-58 主分支集成与最终门禁报告

日期：2026-08-31
范围：`DYDATA-56 -> DYDATA-8 -> DYDATA-14 -> DYDATA-15 -> DYDATA-34 -> DYDATA-58 foundation -> DYDATA-70 -> DYDATA-58 remaining`。
结论：**LOCAL FUNCTIONAL GREEN / RELEASE BLOCKED**。

## 1. 已完成实现

- 线索主档支持一条主档关联多个来源标识，来源记录与主档映射可追溯。
- 总部池、规则版本/试运行、正式轮次和历史 legacy 修复边界闭合；运行时不再创建 legacy 轮次。
- 自动正式分配和自动再分配保持关闭；已有正式轮次仍可跟进。
- 父任务按上海自然日生成子任务，单日独立 session、提交和恢复；影响集合驱动线索与结算增量处理。
- 结算使用 immutable result lineage、增量 rebuild、generation projection 和 current pointer，不再全量删除后重建。
- 最高管理员可查看任务事实并提交受控命令；Ops Agent 仅允许重启 worker/browser，具备唯一容器匹配、租约 fencing、冷却和审计。
- worker/browser/API/ops-agent 配置资源上限、日志轮转和 `no-new-privileges`；Docker socket 只挂载到 Ops Agent。

## 2. 调度流程

`父任务 -> 上海自然日子任务 -> 单日采集 -> 记录影响集合 -> 增量线索物化 -> 增量结算 -> 单日提交/关闭 session -> 下一日 -> 必要的最终投影汇总`。

已成功日期跳过；失败日期按有限重试策略恢复；claim 使用数据库租约、owner 和 epoch fencing，旧执行者不能提交被新执行者接管的结果。重型子任务串行执行，不启用日级并发。browser 容器只提供 Chromium/CDP，worker 是 backend aweme 导出的唯一调度来源。

## 3. 数据一致性

- 原始采集与日任务使用稳定业务键和幂等写入，重复日期不会重复插入。
- 线索增量闭包只处理受影响订单、来源标识和主档；状态版本防止旧观察覆盖新状态。
- 历史 legacy 仅允许在状态修复中被关闭，不再由运行时创建；trial 不被修复脚本冒充正式轮次。
- 结算调整始终关联 immutable original fee result；versioned carryforward 只投影当前 application。
- projection generation 先生成、校验再切换 current pointer，失败 generation 不覆盖当前可读结果。

## 5. 内存峰值

本机是 Windows，未提供 Linux `/proc`、cgroup、swap 或 OOM 指标。合成 benchmark 的 `process_tree_rss_peak_bytes`、`host_used_peak_bytes`、`swap_used_peak_bytes` 等资源字段仍为未验证；因此本轮没有可与生产事故峰值直接比较的真实内存数据。

代码层已加入批处理、单日 session 释放、worker 3 GiB 容器上限、进程树/cgroup/主机/swap 采样与停止阈值，但这些保护必须在目标 4C/8GB Linux 环境实测后才能签发。

## 6. 生产风险

1. 未验证真实 PostgreSQL 下的 `FOR UPDATE SKIP LOCKED`、租约回收、epoch fencing 和并发 current pointer 切换。
2. 未验证 4C/8GB Linux 三轮 worker RSS、主机峰值、swap headroom 与 OOM 行为。
3. 未在压力运行中同步探测 HTTPS、SSH、API 和 PostgreSQL 可用性。
4. Ops Agent 角色 bootstrap 在数据库仍通过 `PUBLIC` 授予 `TEMP/CREATE` 时会 fail closed；上线前必须先审计 ACL。
5. Linear OAuth 当前失效，issue 状态和证据尚未自动回写。

## 7. 分阶段上线建议

1. 在独立、可丢弃 PostgreSQL 测试库执行迁移全链、日任务失败恢复、重复日期、跨日线索和月度结算验证。
2. 在 4C/8GB Linux 使用脱敏且至少约生产两倍规模 fixture 连续运行三轮，保存资源和可用性报告。
3. 先以 shadow 模式运行新投影，不切换生产 current pointer；核对 checksum、行数和关键聚合。
4. 通过发布授权后再单独部署，先 canary 一个日期窗口；观察 worker、API、PostgreSQL 和主机资源。
5. 任一资源、等价性或可用性门禁失败即停止，使用旧读取结果和 durable checkpoint 回退；不通过增加 swap 掩盖问题。

本报告不授权生产部署、生产重启、数据迁移或自动分配/再分配启用。
