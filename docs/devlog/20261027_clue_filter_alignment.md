# 线索核销明细对齐与手机号精准筛选

## 用户确认与范围

用户明确授权与 DYDATA-106 一并完成开发、合入主分支及部署。保留 `is_self_store_verified` 的原有跟进考核语义；线索明细用于解释指标看板，不能以成功跟进为条件，也不能因轮次摘要未回填而漏筛。手机号采用完整中国大陆手机号码精准匹配。

## 实现

- 明细列表、导出及单条详情通过原始券关联核销事实，应用成功、分配后、观察截止前、未撤销及唯一 POI 门店映射条件。多券优先同店；同订单同门店重复分配在自店筛选中按所选范围内最早责任轮次去重。累计与单周都遵守所选分配日期。
- 原轮次考核字段及线索概览的考核计算保留。读取不写业务历史，无需全库回填或数据迁移，也不改变指标看板算法与快照保留契约。
- 客户手机号仅通过 POST 请求体传输，校验完整号码、清空重置分页；匹配原始明文或与当前密文来源一致的已有缓存，不调用抖音接口、不查询时全库解密。门店权限与组合条件在服务端继续生效。
- 输入不放入 URL、浏览器存储、导出响应头或普通日志；数据库异常隐藏绑定参数。号码缺失、掩码或无法验证当前来源时不猜测匹配。
- 发布入口修复已有 mixed-owner 源码替换失败：校验归档、路径、容量及旧源码身份，互斥执行，保留一代源码并可在切换失败时恢复；继续调用原部署脚本的备份验证、轮换、迁移、预热与健康检查。
