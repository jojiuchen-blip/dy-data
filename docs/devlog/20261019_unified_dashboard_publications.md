## 环境问题与边界

系统 Python 的第三方 `tests` 包导致首次全仓收集失败；已建立独立虚拟环境按 requirements 安装依赖并重新运行。新环境缺少对应 Chromium 导致最初四项浏览器 setup error，已安装测试浏览器，后续单独复验。部分旧 API 测试仅插入源事实，缺少显式发布；按业务变更后发布测试版本修正，不在 GET 中添加构建兜底、不降低权限或金额断言。
未执行生产迁移或发布。2026-10-19 04:57 UTC 只读生产容量为 118G 总量、95G 已用、19G 可用、85%；API 约 754/768 MiB。`last-deploy.json` 仍为 `fe02e2a8`。统计估算来源约 51 万订单、8.5 万责任轮次和 37 万结算券，榜单真实构建规模验证仍在补充。最终发布前必须重新核对备份余量、投影体积和构建峰值，部署后再核对磁盘与健康。

独立复查发现筛选元数据授权缓存、线索门店选项版本、组合请求内部 410 恢复和管理费更正实时版本读取四处边界，已完成修复。前端 worker 的 35 项浏览器场景通过，覆盖首次请求内版本过期、同版本权限缩小、静态 pending 行读取实时 current、更正 409 显式重读，以及 GET/POST/分析请求 401/403 清表单和拒绝晚到响应；主树仍须完整集成验收。浏览器合成接口测试已接入 pytest，不依赖额外安装 Node Playwright 包。

榜单真实构建规模测试发现责任轮次批量查询遗漏字段导致逐条补查，以及质量汇总 NOT IN 子查询导致反复扫描。已补齐窄字段并启用禁止懒加载的哨兵，名单去重后使用 LEFT JOIN，订单在合并指标前按原组织维度聚合；保留旧口径对照。正常构建一轮 85.463 秒、Python CPU 34.25 秒、进程峰值 RSS 94.805 MiB，属于本地不限 CPU 环境，不能替代 0.5 CPU 生产限额验证。带 tracemalloc 的诊断达到 180 秒限制，未得到完整 Python 分配峰值；不将仪器开销当正常构建耗时或放宽限时。

全仓诊断另发现有效推广发票分摊关联旧账单版本时漏计金额，已修复为保留原分摊身份的窄金额事实，当前账单金额不重复累计；原 HTTP 金额断言及 SQLite 21 项、PostgreSQL 8 项回归通过。管理费实时 GET 的 10 项 HTTP 与原更正流程通过。

最终 PostgreSQL 集成一轮为 44 通过、1 跳过、1 失败。唯一失败来自强制结束 Windows 子进程后，数据库连接尚未释放模块锁；测试随后读取因锁仍被占用正确返回未执行。修复仅在测试加入有超时的 PostgreSQL 同模块锁同步检查，保留原 SOURCE_BUSY、旧版继续 active、旧 building 记失败及事实未增加断言；连续三次独立复验通过。该局部结果尚不等于最终全仓通过。

真实规模最终正常构建为 86.551 秒、Python CPU 35.5 秒、峰值 RSS 100,007,936 B。首个全局汇总读为 87.025 秒，随后为 0.960/0.947 秒；全局筛选元数据为 0.327/0.327/0.264 秒，因此仍未满足完整页面秒内目标。首读期间 PostgreSQL 首次自动分析新投影表；之后 EXPLAIN ANALYZE 为 993.825 毫秒、没有 JIT，估算接近实际行数。首读执行计划未留存，不能断言具体慢节点；发布前准备统计信息的修复仍在验证。原诊断子进程把后续读取算入 180 秒总时长而中止，不应描述为 builder 超时。

生产首版发布存在外部阻碍：只读检查发现两个 `parent_sync` 与一个 `date_sync` 处于 `retry_wait`。父任务分别记录 `worker_exit_1`，日期任务为 2026-07-31、`douyin_rate_limited`、下次重试 2026-10-20。它们会触发来源就绪保护，不能直接执行首版预热或以改任务状态绕过。此处尚未对这些既有任务执行恢复、取消或其他写操作。

容量只读复核：根盘可用 19,542,118,400 B（15.42%），距离 15% 阈值约 0.50 GiB。最近有效备份 1,801,151,205 B，当前满足备份空间公式，但部署镜像构建先于备份检查，现有余量不能证明足够容纳构建峰值。六份普通备份及专项回退点保持保留；旧导入 chunks、无引用镜像仅登记为待复核候选，本轮未执行清理。不得将 Docker 名义可回收总量直接写成已释放空间。
