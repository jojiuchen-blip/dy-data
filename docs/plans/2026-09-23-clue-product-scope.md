## 既有实现证据

- 指标看板入口为 `apps/web/src/pages/DouyinRankingPage.tsx`，正式 API 为 `apps/api/dy_api/routes/dashboard.py` 的 `/dashboard/douyin-ranking` 和导出接口。
- 实际统计由 `ranking_business.py` 与 `ranking_snapshots.py` 负责，不能只修改旧版 `douyin_ranking.py`。
- 正式快照当前按精诚养车 SKU/商品规则筛选。快照缓存以时间、指标版本和运行模式识别，增加商品范围必须同步隔离缓存，不能复用其他范围的结果。
- 线索明细及看板共用 `ClueCenterPage.tsx`；后端筛选集中在 `routes/_data.py` 的 `_clue_where`，目前商品条件是细分类精确匹配。
- 线索接口保留正式轮次、已有日期边界及服务端账号门店权限；组织筛选只能进一步收窄。
- `docs/rules/account-access-control.md` 规定集团与服务中心是独立维度，区域需完整组织路径；指标打榜已有独立权限例外，本次不扩展线索明细权限。
- 仓库部署入口为 `.github/workflows/tencent-lighthouse-deploy.yml`，生产发布须经过验证阶段。

## 目标行为

1. 指标看板新增全部商品、精诚养车、比亚迪本品三种范围，保持原有日期、归属、去重、跟进与核销公式。精诚养车沿用配置识别；在其余原有有效性规则不变的条件下，比亚迪本品严格为全部减去精诚养车，包括未匹配到精诚养车规则的商品，不因空值漏失。
2. 线索明细商品筛选只显示相同三项，全部商品是查询范围，不写成某条记录的商品类别。不修改后台商品口径配置或分配策略。
3. 线索看板固定提示：该指标与考核标准不完全一致，如需查看考核指标请以指标看板板块为准。
4. 线索明细增加全部、集团、中心、大区、区域、门店的范围筛选，候选项可搜索；切换上级清除失效下级，筛选改变重置分页，清空筛选恢复默认状态。候选项、列表、数量与导出一致遵循当前账号权限。

## 实现边界

- 复用现有配置及查询服务，分类以服务端为准，不靠商品名称猜测。
- 商品参数贯穿页面请求、统计、缓存、下钻与导出；精诚养车模式需与原实现结果一致。
- 组织目录复用当前生效正式组织归属，集团不错误地成为中心的必选父级，同名区域使用完整路径。
- 使用现有 SelectField/搜索控件与设计令牌，不改版页面，不新增角色，不开启自动分配或重建历史责任。
- 独立工作树基于 origin/main，不带入其他工作目录的未提交内容。上线前重新核对主分支，禁止强推。
