## 6. 风险与应对

| 风险 | 应对 |
|---|---|
| 业务口径漂移 | 不汇总每日 distinct/分位；冻结轮次与有效历史，SQL 选择区间内责任后聚合；与旧逻辑交叉验证。 |
| 版本不完整 | 后台完整构建后原子切换；构建失败继续读取上一版；业务物化未结束时延后。 |
| 磁盘与内存 | 窄投影、批量写入、普通两版与显式 pin；不复制原始 JSON，不为筛选组合建副本。 |
| 权限泄露 | 服务端每次按当前权限过滤；浏览器缓存隔离账号，版本号不授予权限。 |
| 结算 lineage 被误删 | 不把结算 generation 当通用发布表，不清理其祖先或账单历史。 |
| 上游 PR50 仍未合并 | 保留明确依赖；最终合入前重新核对，不用陈旧 main 覆盖线上修复。 |
| 生产来源尚未就绪 | 三个采集任务处于 retry_wait，首版预热被保护逻辑阻止；先核对恢复状态，不以修改任务状态绕过。 |
| 构建峰值容量未验收 | 可用空间仅略高于 15%，普通备份及专项回退点需保留；完成精确容量核对后才可部署。 |
