## 0. 本计划使用指南

AI 执行代码核对、实现及验证，人类审核接口范围与交付结果。此计划仅覆盖源系统接口，不将本机 PDCA 的测试结果当作源接口验收。

### 0.1 PRD 加载约束

先读 [mainprd](../../prd/mainprd-dy-data.md)，再读子计划列出的 Schema、API、代码及测试。原 PRD 的结算口径不直接套用到 PDCA。新接口契约需单独审核，不能修改旧 PRD 意义来绕过缺口。

### 0.2 读前门禁 / AI 自检清单

- 任务初始待审阅；人工审阅通过后才可切换待开发。
- 核查 git status，保留既有未提交内容；本任务不得覆盖 ranking_source_evidence 等既有文件。
- 补读关联 foundation 分文件并明确字段语义；如定义和模型冲突，保留缺口，不猜测。
- 新接口的身份校验和数据库会话不得触发业务写入；若现有依赖存在隐式写入，停止并报告，不改原认证流程。
- 实装前通过 main/kanban/sub 一致性门禁和任务环境检查。

### 0.3 完成前验证门禁

先写失败测试，再实现，再执行专项、全量后端测试和前端构建。真实生产查询及上线单独确认；本地测试通过不得宣称生产已接通。
