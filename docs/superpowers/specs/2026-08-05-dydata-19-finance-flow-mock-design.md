# DYDATA-19 财务开票全流程 Mock 设计说明

> 状态：待用户书面审阅后进入页面实现
> 日期：2026-08-05
> 需求来源：Linear `DYDATA-19`、关联任务 `DYDATA-31`、财务流程确认稿及本对话已确认备注

## 1. 目标

本轮先交付一套可在浏览器操作的高保真 Mock，用于向公司财务展示并复核完整业务流程。Mock 同时覆盖门店端和财务端，重点验证：

1. 月末系统排查、门店确认、6 日自动确认和异议处理如何衔接。
2. 门店确认金额后如何开具推广服务费发票、提交发票信息并查看审核结果。
3. 财务如何在系统外完成审核打款，再将结果批量导回系统。
4. 管理服务费发票、SAP 编码差异、导入记录和账单重算如何处理。
5. 页面字段、状态文案、异常提醒和权限边界是否足以进入后续 PRD 与开发。

## 2. 方案选择

采用“独立可交互全流程 Mock”，不直接改生产业务页面。

选择理由：

- 财务会议需要从门店端和财务端连续演示，独立 Mock 更适合预置多种业务状态。
- 当前重点是确认流程和页面逻辑，不需要先绑定真实 API、权限或数据库。
- 确认完成后，可将页面交付清单和交互语义反推为 PRD、状态机、数据模型与 API 需求。

本轮不采用：

- 直接在生产 React 页面实现：业务口径仍需要财务最终复核，过早绑定真实数据会扩大返工范围。
- 仅输出静态图片或文档：无法验证筛选、弹窗、导入、状态切换和跨页跳转。

## 3. 实现边界

- Mock 工程位置：`docs/prototypes/dydata-19-finance-flow-dashboard/`。
- 使用前端本地 Mock 数据，不调用真实后端，不写入数据库。
- 角色切换器仅用于演示；正式产品根据登录账号权限决定端口和可见动作。
- 财务在文档和页面中统一写作“财务（系统权限：管理员角色）”。不新建独立财务角色。
- 复用 dy-data V0.2.1 设计系统：浅色/深色主题、品牌橙、表格、表单、按钮、弹窗和导航规则。
- 桌面 1440px 为财务会议主展示尺寸，同时保证 768px 与 390px 可用。

## 4. 角色与权限

| 角色 | 数据范围 | 可执行动作 |
|---|---|---|
| 门店 | 仅本门店 | 查看账单、确认金额、发起异议、填写推广服务费发票信息、查看审核结果、查看管理服务费发票信息、维护或导入本店 SAP 编码 |
| 管理员 | 授权门店 | 财务页面全部查询与导入、处理 SAP 差异、处理账单金额异议、确认费率调整、查看审计历史 |
| 最高管理员 | 全部门店 | 与管理员相同；本需求不再按产品类型或精诚养车单独限制处理权限 |
| 系统 | 全局 | 月末排查、自动确认、格式与重复性校验、状态流转、差额结转、通知和审计留痕 |

## 5. 信息架构

### 5.1 门店端

一级模块沿用“结算”，本 Mock 提供三个稳定子页面：

1. 月度账单
   - 查看推广服务费、管理服务费两个费用方向。
   - 展示账单总额、已确认金额、待确认金额、账单版本和确认截止时间。
   - 执行账单确认或进入账单详情发起异议。
2. 推广服务费开票
   - 查看待开票账期与开票信息。
   - 一键复制购买方和开票要求。
   - 填写发票信息、提交系统校验、查看厂端审核结果。
3. 发票与调整记录
   - 查看推广服务费历史发票、审核原因和下账期调整。
   - 查看厂端开具的管理服务费发票号码、金额和开票时间。
   - 查看历史异议和处理结果。

### 5.2 财务端

新增一级页面“财务”，仅管理员和最高管理员可见。一级页只承载页面说明和四个二级入口，不展示待办数量或金额；相关汇总放在各二级页面顶部。

四个二级页面：

1. 推广服务费
2. 管理服务费
3. 账单异议
4. 导入记录

“账单异议”包含两个稳定三级页面：

- SAP 编码异议
- 账单金额异议

账单金额异议采用统一列表，并根据异议类型显示对应处理动作，不按产品类型拆分页面。

## 6. 月度账单与确认流程

### 6.1 时间规则

1. 月度结束后，只要系统处于联网状态，即开始自动排查上月数据。
2. 首要排查项为数据是否齐全；系统异常或数据不齐全时阻断自动确认。
3. 修复完成后系统自动恢复排查与确认流程。
4. 次月 1 日至 6 日为门店主动确认期。
5. 6 日 24:00 对仍未确认且无系统阻断的费用方向执行自动确认，节假日不顺延。
6. 10 日 24:00 为推广服务费发票提交成功的当月结算截止时间，节假日不顺延。

### 6.2 确认粒度

- 门店操作统一称“账单确认”。“锁账”仅作为兼容性内部术语，不出现在门店主要操作文案中。
- 按“费用方向 + 账单版本”分别确认并冻结。
- 推广服务费与管理服务费互不阻断。
- 门店只要确认金额，即可进入该费用方向的后续开票流程。

### 6.3 确认状态

`系统排查中 → 待确认 → 已确认`

异常分支：

- 数据不齐全：`系统排查中 → 系统异常，待修复 → 修复后重新排查`
- 门店发起异议：`待确认 → 异议处理中 → 已确认`
- 门店未操作：`待确认 → 6 日 24:00 系统自动确认 → 已确认`

## 7. 账单异议流程

### 7.1 发起规则

- 异议入口存在但不突出，放在账单详情二级菜单内。
- 门店必须先查看订单明细，才能发起异议。
- 异议类型：费率设置错误、订单遗漏、其他。
- 必填内容：争议订单、争议金额、说明、证明材料。
- 发起后系统先自动检测数据，并把检测结果与异议一起提交给管理员。

### 7.2 阻断规则

- 任一费用方向存在异议时，该方向整期不确认。
- 该方向已确认金额为 0，全部金额保持待确认。
- 不允许无争议部分先确认或先开票。
- 另一个费用方向不受影响。

### 7.3 处理状态与结果

状态：`系统检测中 → 处理中 → 已处理 / 已驳回`

- 异议不成立：管理员填写驳回原因；系统按原金额自动确认，无需门店再次确认。
- 异议成立且为漏单或跑数错误：系统重跑并生成新版本金额，处理完成即自动确认，无需门店再次确认。
- 异议成立且为费率错误：管理员或最高管理员重新设置费率并选择生效日期；系统生成新版本，处理完成即自动确认。
- 费率生效日期默认当月。若选择更早日期并影响已打款账期，必须二次确认；原打款结果不变，重算差额进入下一账期。

## 8. 推广服务费开票流程

### 8.1 门店开票前信息

系统展示并支持一键复制：

- 购买方：比亚迪汽车销售有限公司。
- 发票项目：推广服务费。
- 税率：6%。
- 当前应开票价税合计。
- 可覆盖的连续完整账期。

门店前往开票系统完成开票，不使用“线下开票”表述。

### 8.2 发票提交字段

必填：

- 数电专票号码：20 位纯数字。
- 开票日期。
- 不含税金额。
- 税额。
- 价税合计。

不采集：发票附件、备注、红字发票号码、红冲完成时间。

### 8.3 强校验

- 购买方必须为“比亚迪汽车销售有限公司”。错误提示：`发票对象开具错误，请检查开具至【比亚迪汽车销售有限公司】发票`。
- 税率必须为 6%。错误提示：`发票税率错误，请开具6%税率的推广服务费发票至比亚迪汽车销售有限公司`。
- 价税合计必须等于所选全部账期的已确认推广服务费。
- 发票号码必须为 20 位纯数字，且不能与其他有效提交重复。
- 系统不校验年份前缀，不调用外部验真服务。

### 8.4 账期占用

- 一张发票可以覆盖多个连续且完整的账期。
- 一个账期必须全额开票，不能拆成多张发票。
- 一个账期被有效提交占用后，不能被另一张发票重复提交。
- 审核不通过后，原发票退出已开票金额并释放账期，门店可重新提交新发票。

### 8.5 状态机

`待开票 → 已提交发票，待系统校验 → 提交成功，待厂端审核 → 审核通过，已结算`

失败分支：

- 系统格式、金额或字段校验失败：留在填写页，门店修正提交信息后重新提交，不一定需要重新开票。
- 厂端审核不通过：`审核不通过，请红冲重开`；必须展示原因，原发票退出已开票金额并释放账期，提醒门店红冲后重新开票。

### 8.6 结算规则

- 只看系统记录的提交成功时间，不看发票日期。
- 10 日 24:00 前提交成功且审核通过：计入当月结算。
- 10 日 24:00 后提交成功：进入次月结算。
- 审核通过即代表全额打款完成，直接显示“审核通过，已结算”。
- 不支持部分打款，不展示“待结算、部分结算、未结算金额”等中间状态或字段。

### 8.7 门店汇总字段

- 推广服务费总额。
- 已确认金额。
- 已开票金额：从提交成功开始统计；审核不通过后退出。
- 发票审核通过金额。
- 发票审核未通过金额。

不单独展示已结算金额和未结算金额。

## 9. 财务审核结果回填

1. 门店发票提交成功后，全部记录进入财务“推广服务费”页面。
2. 财务在系统外完成发票审核与打款。
3. 财务将发票号码、审核状态和失败原因批量导入系统。
4. 唯一匹配键为发票号码。
5. 审核通过必须全额，导入结算金额必须等于发票价税合计。
6. 审核不通过时失败原因必填；系统同步更新门店端并提醒红冲重开。
7. 导入采用整批原子校验：任一行失败则整批失败，不允许部分成功。

## 10. 管理服务费发票

- 开票方向：厂端向门店开具。
- 财务页面展示全量记录，不需要先筛选已确认账单。
- 财务批量导入发票号码、发票金额和开票时间。
- 一个门店、一个账期默认对应一张发票。
- 门店端只展示发票号码、发票金额和开票时间，不提供附件查看或下载。
- 状态仅为：`待开票 → 已开票`。

## 11. SAP 编码差异

- 门店维护 SAP 编码；财务可批量导入 SAP 编码列表。
- SAP 编码不是推广服务费发票提交的必要字段；SAP 不一致不阻断推广服务费发票提交。
- 门店值与财务导入值不一致时，先提示处理。
- 主列表处理完成后只显示一个字段：`有效 SAP`。
- 详情与审计历史保留门店原值、财务导入值、选择结果、操作人和时间。
- 门店或财务均可确认；财务可在权限范围内代门店确认。
- 支持单条操作、导出待确认清单、导入确认清单。
- 门店导入新值时允许覆盖原值，但必须先提示确认。

## 12. 已开票、已打款后的重算

| 场景 | 处理 |
|---|---|
| 已开票未打款，重算金额一致 | 原发票继续审核打款，不提醒门店 |
| 已开票未打款，重算金额不一致 | 提醒门店；原发票继续审核打款；差额进入下一账期 |
| 已打款后发现漏单、跑数或追溯费率变化 | 提示确认；不修改原发票、原打款和原结算结果；差额进入下一账期 |
| 下账期差额为负数 | 作为负向调整继续结转，直至被后续正向金额抵扣；不生成负数待开票金额 |

费率重新设置默认不影响已打款账期，只有明确选择追溯生效日期时才计算差额。

## 13. 财务二级页面设计

### 13.1 推广服务费

顶部汇总：推广服务费总额、已确认金额、已开票金额、审核通过金额、审核未通过金额。

列表字段：门店、有效 SAP、账期、账单版本、推广服务费总额、已确认金额、发票号码、不含税金额、税额、价税合计、开票日期、提交成功时间、审核状态、审核原因、结算归属月、更新时间。

页面动作：筛选、查看详情、导入审核结果、查看导入记录。

### 13.2 管理服务费

顶部汇总：管理服务费总额、已确认金额、待开票金额、已开票金额。

列表字段：门店、有效 SAP、账期、账单版本、管理服务费总额、已确认金额、发票号码、发票金额、开票时间、状态、更新时间。

页面动作：筛选、查看详情、批量导入发票信息、查看导入记录。

### 13.3 账单异议

三级页面一：SAP 编码异议。

- 顶部展示待确认数量和已确认数量。
- 列表主字段只展示有效 SAP；详情展示差异原值。
- 支持单条确认、导出待确认清单、导入确认清单。

三级页面二：账单金额异议。

- 顶部展示系统检测中、处理中、已处理、已驳回的数量与争议金额。
- 统一列表展示费率错误、订单遗漏和其他异议。
- 详情根据类型显示系统检测结果、订单证据、费率日志和对应处理动作。

### 13.4 导入记录

统一承载四类导入：

- 推广服务费审核结果。
- 管理服务费发票信息。
- SAP 编码列表。
- SAP 确认结果。

列表字段：批次编号、导入类型、文件名、记录数、状态、导入人、导入时间、校验摘要、覆盖版本。

规则：

- 原始无数据：直接导入成功，不需要确认。
- 内容一致：幂等成功，不产生业务变化。
- 内容不同：预览差异并提示确认覆盖。
- 重复导入、漏行、未知号码或金额不一致：整批失败并展示可定位的行级原因。
- 确认覆盖后以最新版本为准，旧版本永久保留。

## 14. 跨页面交互

- 同一业务对象使用同一任务编号和状态，避免多个页面各自维护副本。
- 汇总卡、状态筛选和详情页支持深链接；刷新和浏览器前进后退后仍保持页面状态。
- 门店端审核失败记录可跳转到对应待开票账期重新提交。
- 财务页面的发票、异议、导入批次可相互跳转。
- 并发修改时，旧版本提交被拒绝，并提示刷新后重新操作。
- 所有批量覆盖、追溯费率和不可逆状态更新使用确认弹窗。
- 系统内通知为 V1 唯一通知渠道；本轮不接短信、邮件或企业微信。

## 16. 验收标准

1. 门店端和财务端的所有页面均可通过浏览器点击访问，不依赖后端。
2. F01-F10 均可在 Mock 内复现，并能看到正确状态、金额和提示文案。
3. 门店端不存在突出异议入口，也不存在“锁账”主操作文案。
4. 财务一级页不展示待办数量；四个二级页面各自展示相关汇总。
5. 发票强校验、整批导入失败、覆盖确认、审核失败红冲和下账期差额均有可交互反馈。
6. 页面仅展示有效 SAP；差异原值只在处理详情与历史中出现。
7. 1440px、768px、390px 无明显水平溢出，键盘焦点可见，颜色不是唯一状态提示。
8. 浅色和深色主题均可用，关键文字达到 WCAG AA 对比度。
