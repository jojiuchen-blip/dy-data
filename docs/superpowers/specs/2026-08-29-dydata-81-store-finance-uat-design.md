## 1. 目的

提供一个只读、可本地访问的门店端 UAT 预览，使用户先验收二级导航、页面 Shell、模块顺序、字段位置、响应式布局、合法空态和跨页跳转关系。它不是正式系统、不是临时看板的演示复制品，也不承担业务数据写入或生产验证。

验收二级导航及固定顺序：

1. 全国门店榜单；
2. 单店分账；
3. 开票确认；
4. 发票状态查看；

“订单费用明细”不再作为独立二级入口；推广费明细、管理费明细和账单异议作为“单店分账”内的顺序模块验收。

## 2. 权威边界

| 层级 | 本 UAT 必须遵守的来源 | 不得使用的来源 |
|---|---|---|
| 外框、一级/二级导航、视觉 token、组件密度、响应式 | 主系统现有 Shell 与视觉规范 | 临时看板的页面外壳、旧 UAT 的试运行提示 |
| 页面内部模块、操作顺序、状态呈现、跳转 | `codex/dydata-19-finance-mock@9a574fa`、页面合同矩阵、用户确认截图 | “功能类似”的自行简化或换位 |
| 金额、日期、状态、权限与公式 | 最新用户确认、DYDATA-19 / DYDATA-31、正式 API | 演示金额、测试账期、推测状态、前端补零 |
| UAT 数据 | 正式 API 的只读返回；门店手工填写仅作为空表单输入 | mock 回退数据、伪造日期、伪造确认成功、伪造审核状态 |

UAT 不读取、修改、重构、格式化或删除任何 `/finance/*` 页面、接口、导航、权限或测试。

## 3. 方案选择

| 方案 | 说明 | 结论 |
|---|---|---|
| A. 独立只读 UAT 预览（采用） | 使用主系统的视觉语言和 Shell 关系，单独承载 UAT 路由；仅消费 GET 数据，所有无数据状态如实呈现。 | 能先验证视觉合同，不污染正式路由、业务数据或财务端。 |
| B. 在正式页面中植入演示状态 | 在现有页面加测试账期、零金额、已确认/审核状态，方便点击演示。 | 拒绝：会把演示数据和状态带入正式系统，违反已冻结边界。 |
| C. 直接改正式页面并对真实账单做写入联调 | 在 UAT 身份下确认账单、登记发票并验证跳转。 | 延后：需通过页面合同、开发计划、真实 UAT 授权和 Given–When–Then 写操作门禁。 |

## 4. UAT 架构与数据流

### 4.1 隔离方式

- UAT 是独立入口，不替换或覆盖正式路由的实现；启动后由本地服务输出实际访问地址。
- 它复用主系统的间距、颜色、字体、卡片、表单和导航规则，但不复用临时看板的演示数据或提示文字。
- 任何 API 调用仅允许 `GET`；不调用账单确认、发票登记、异议、导入、生命周期或 `/finance/*` 写接口。
- 读取失败、权限不足、无账单、无发票时，保留真实错误/空态；绝不降级为本地样例。

### 4.2 数据契约

| 数据类别 | 允许来源 | UAT 渲染规则 |
|---|---|---|
| 当前登录门店 | 正式会话的绑定门店信息 | 自动选中，不提供越权切换。 |
| 账期 | 正式 API 的最新业务账期 | 无返回时显示“暂无数据”，不使用浏览器当前月份。 |
| 金额/指标 | 正式 API 或经确认的服务端派生结果 | 无返回时显示“暂无数据”，不显示 `¥0.00`。 |
| 状态/时间 | 正式 API | 无返回时显示“尚未生成”或“待确认”，不伪造流程节点。 |
| 发票填写字段 | 门店手工输入 | 可以展示空表单；校验/提交在此 UAT 中不写入。 |

### 4.3 跳转语义

推广服务费在**正式 API 已确认成功**时，卡片显示“进入推广费开票”，跳转开票确认并带入服务端确定的门店、完整账期组和账单版本。开票页提供“复制全部开票信息”引导。管理服务费确认不跳推广开票。

只读 UAT 不伪造确认成功：若当前没有正式已确认推广账单，确认按钮只能呈现不可操作的合法状态，不能通过本地点击制造跳转。真实确认写入与跳转 GWT 留在后续获得单独授权的正式 UAT 联调阶段。

## 5. 五页视觉与交互合同

### 5.1 全国门店榜单

- 页面标题只保留“全国门店月度榜单”，删除标题下的小字说明。
- 筛选区保留正式 API 支持的字段；排序项仅限榜单指标集合。
- 指标卡固定为：销售金额（累计）、核销金额（累计）、当期推广服务费、累计推广服务费。
- 表格列固定为：排名、门店、销售金额、核销金额、当期推广服务费、累计推广服务费。
- 管理服务费、结算参考、销售订单、核销订单和演示提示不展示。
- 列表空时显示“暂无数据”，不显示假排名或金额。

### 5.2 单店分账

- 删除门店名称 + 测试账期 + 预览口径的展示模块，删除所有“测试”“预览”“试运行”业务提示。
- 保留主系统筛选器和一行指标卡轨道；无数据时卡片值为“暂无数据”，而非零金额。
- 当前账单确认区保持左右并列：推广服务费确认、管理服务费确认。两个方向各自显示真实状态、金额或“尚未生成”。
- 自动确认边界固定为北京时间每月 6 日 24:00；系统状态仅由正式 API 反映。
- 推广服务费确认成功后显示开票入口；管理服务费确认完成后保持厂端开票的只读语义。

### 5.3 开票确认

- 删除七节点时间轴、当前环节提示、门店 ID/系统确定开票账期/指标口径区、紧邻错误条、推广费账单表、左栏“当前开票账期”说明框。
- 首屏核心为等高左右两栏：左栏“收票方与开票信息”，右栏“填写数电专票信息”。
- 左栏保留用户确认的比亚迪汽车销售有限公司基准资料及“复制全部开票信息”动作。
- 右栏字段只保留购买方名称、填写人电话、税率、开票日期、20 位数电专票号码、不含税金额、税额、价税合计；桌面每两个字段并列，移动端单列。
- 字段规则只在系统校验后按字段返回；不预置一整块“校验规则”或静态错误列表。
- UAT 可展示空表单和真实 API 可读金额；不允许提交或登记发票。

### 5.4 发票状态查看

- 推广服务费汇总固定五项：账单总额、已确认金额、已开票金额、审核通过/已结算金额、待开票金额。
- “审核不通过”保留为记录状态、原因和重开事实，不作为第五张指标卡。
- 待开票金额由服务端提供 `pendingInvoiceAmount`，覆盖已确认待开票与审核不通过后整体释放、可重开金额；前端不本地累加，避免重复计算。
- 保留推广发票记录、管理服务费发票信息和差额台账的结构。后两者没有正式 API 数据时，显示“暂无数据”，不得以财务端数据、导入文件或演示值补足。
- 发票号搜索遵循“绑定门店权限范围 → 服务端精确发票号匹配 → 对结果分页”；默认账期不得先排除跨账期命中。
- 不展示“待开票”作为推广发票记录状态筛选项。

### 5.5 订单费用明细

- 不再作为独立二级导航入口或独立 UAT 路由。
- 在“单店分账”的两张确认卡之后，依序呈现“费用明细（推广费明细 / 管理费明细）”和“账单异议”。
- 两个费用明细子页在无正式 API 结果时显示“暂无数据”，不擅自增加字段、金额、筛选或演示表格。
- “账单异议”位于两类明细的最下方；无当前可发起账单时保留合法空态和低强调入口，入口可打开字段核对表单，但只读 UAT 不提交成功、不上传证明资料或伪造状态。

## 6. 响应式与视觉验收

| 视口 | 验收要求 |
|---|---|
| 1440 px | 导航完整可见；榜单/单店指标卡保持同一行；单店确认与开票两栏并列且边缘、标题、字段基线对齐。 |
| 768 px | Shell、筛选和表格不重叠；必要时横向滚动表格；双栏在仍可读时保持并列。 |
| 390 px | 指标卡采用可横向滚动的单行卡轨道，不竖向堆叠为大量大卡；开票表单变为单列；底部/顶部导航与内容不遮挡。 |

三档页面都必须移除本规格列出的无意义占位、演示口径和测试模块，并保留真实空态。开票确认页的业务时间节奏按第 10 节保留；它不是演示时间轴，也不显示伪造的当前阶段。

## 7. 验收证据与失败处理

### 7.1 必须产出的证据

1. 四个二级页面及单店分账内“推广费明细 / 管理费明细 / 账单异议”在 1440、768、390 的并排截图；
2. 每页的正常空态、真实有数据态（若 API 返回）和 API 错误态截图；
3. 跳转 Given–When–Then：仅在 API 已确认推广账单存在时验证确认后进入开票确认；
4. 只读网络记录，证明没有 UAT 写请求和没有 `/finance/*` 调用；
5. 页面合同矩阵逐行标识 `PASS`、`APPROVED DEVIATION` 或 `BLOCKED`。

### 7.2 失败处理

| 情况 | UAT 行为 |
|---|---|
| 无正式数据 | 显示“暂无数据”或“尚未生成”，保持结构但禁用写动作。 |
| 401/403 | 显示权限提示，不切换门店、不回退到样例。 |
| 5xx/网络失败 | 显示可重试的真实错误，不补日期、金额或状态。 |
| API 缺字段 | 对应模块标记“数据暂不可用”，不从其他页面或本地计算推断。 |
| 合同冲突 | 保持 `BLOCKED`，回到用户裁决，不自行选择。 |

## 8. 非目标与进入正式实现的门禁

本 UAT 不执行账单确认、发票登记、异议提交、导入、状态流转、真实开票、审核、结算或生产部署；不替代 DYDATA-81 正式交付。

只有以下条件同时成立，才能从 UAT 进入正式系统实现：

1. 用户书面审阅并通过本规格及更新后的页面合同矩阵；
2. DYDATA-81 对应正式开发计划存在一个已审阅、状态一致的进行中任务；
3. 管理服务费、差额台账、五项汇总和跨账期发票号搜索的门店端 API 合同已确认；
4. 真实门店 UAT 权限、无数据/有数据/错误数据和写操作授权范围已确认；
5. `/finance/*` 受保护范围核查通过。

## 9. 规格自检

- 未引入演示金额、账期、状态、提示或伪造跳转；
- 已把用户确认的五项指标、待开票金额组成与审核不通过记录语义分离；
- 明确了 UAT 可验证的只读行为与仍被阻断的真实写操作；
- 未把管理服务费门店查询替换为财务端功能；
- 页面、数据、异常和响应式要求均能映射到页面合同矩阵。

## 10. 2026-08-30 UAT 评审修订（最高优先级）

本节是用户对 UAT 的最新明确确认。与前文、旧评论或临时看板演示规则冲突时，以本节为准。

### 10.1 全国门店榜单

- 在“门店排名”表格标题行右侧增加“排行依据”。
- 选择项只能是榜单业务指标：销售金额（累计）、核销金额（累计）、当期推广服务费、累计推广服务费；不包含“门店”，不新增未经确认的指标。
- UAT 中选择只改变控件自身状态；没有正式排名结果时不得生成或改排虚构行。

### 10.2 单店分账中的费用明细与异议

- 顶部二级导航删除“订单费用明细”，顺序固定为：全国门店榜单、单店分账、开票确认、发票状态查看。
- 单店分账保留推广服务费确认与管理服务费确认的左右并列结构。
- 确认区之后固定出现“费用明细”，内含两个子页签：推广费明细、管理费明细；两个页签均承接同一门店、账期和费用方向的正式查询契约。
- “账单异议”固定出现在费用明细之后。正式目标仍遵循 DYDATA-19 的费用方向、账期、版本、争议订单、金额、异议类型、说明、联系人、手机号和证明资料字段及服务端状态机；只读 UAT 在没有正式账单时保留合法空态和低强调入口，入口可进入字段核对表单，但绝不模拟提交或上传成功。

### 10.3 开票确认提醒与业务节奏

- 两栏工作区之前展示以下两句用户确认提醒，不替换为演示文案：
  - 门店前往开票系统开具数电专票，再将发票信息上传系统，否则将无法收款。
  - 当月10号前开票提交，当月结算；10号后开票提交将在下月结算。
- 提醒之后、复制全部开票信息和填写/校验两栏之前展示业务时间节奏：月度结束、系统核查、账单确认、自动确认、发票提交、厂端审核、审核通过/已结算。
- 时间节奏展示规则性时间：每月最后一日、次月 1 日、次月 1—6 日、次月 6 日 24:00、当月 10 日前、以厂端结果为准、以实际结算为准；开票确认页将“发票提交”作为当前页面节点高亮，但不把该视觉定位当作正式业务状态。
- 正式数据态的高亮节点必须改由正式 API 返回的生命周期状态映射；UAT 当前仅高亮当前页面节点，不放示例账期/日期/金额，也不据此推断服务端状态。
- 本节覆盖前文“开票确认删除七节点时间轴”的旧 UAT 约定；当前保留的是用户新确认的业务节奏与页面节点高亮，不是旧演示模块。
