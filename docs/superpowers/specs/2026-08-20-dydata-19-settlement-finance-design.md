## 2. 目标与非目标

### 2.1 目标

建立可追溯的业务闭环：

```mermaid
flowchart LR
    A[订单明细] --> B[月度账单]
    B --> C{确认或异议}
    C -->|确认| D[当前有效确认版本]
    C -->|异议| E[管理员处理异议]
    E --> F[生成账单新版本]
    F --> D
    D --> G[系统外开票或厂端开票]
    G --> H[门店登记或管理员导入]
    H --> I[状态查询与财务看板]
    I --> J[导出与操作审计]
```

推广服务费与管理服务费分别确认、分别异议、分别开票、分别计算；账单、确认、发票、结算与调整金额可相互勾稽；当前版本和历史版本均可追溯。

### 2.2 非目标

- 系统不创建开票申请单，不执行真正开票。
- 系统不创建发票待审核任务，不对管理员导入结果做二次审核。
- 不开发企业微信发送或外部发票验真。
- 不把账单异议交给外部处理或导入外部异议结果。
- 不保存原始导入文件。
- 不支持推广费跨门店合票或一个账期拆成多张发票。
- 不为管理服务费设计红冲、作废、替换和重开事件流。
- 本规格不执行生产数据修改或历史迁移。

## 3. 角色与系统边界

系统只有三类角色：

| 角色 | 数据范围 | 主要动作 |
|---|---|---|
| 门店账号 | 仅本店 | 查看和确认账单、提交异议及证明、登记推广费发票、提交 SAP 建议、查询状态和导出本店数据 |
| 管理员 | 全局 | 处理异议、确认或更正 SAP、导入厂端结果和管理服务费发票、查询、导出及审计 |
| 最高管理员 | 全局 | 与管理员权限完全一致 |

财务人员在系统内使用管理员角色。管理员不按门店、区域或其他范围分权。

外部动作与系统动作边界：

| 发生在系统外 | 系统内负责 |
|---|---|
| 推广费真实开票 | 门店登记已开票信息 |
| 推广费厂端审核和结算 | 管理员导入审核及结算结果 |
| 管理服务费厂端开票和扣款 | 管理员导入发票与扣款明细 |
| 外部沟通 | 状态查询、导出和审计，不以沟通结果推进状态 |

## 4. 信息架构与路由

采用按角色拆分的页面结构。

### 4.1 门店端

| 路由 | 页面职责 |
|---|---|
| `/settlement` | 查看月度账单和当前有效版本；分别确认推广费、管理服务费；查看订单明细并提交异议 |
| `/settlement/invoice` | 查看待开票账期；登记推广费发票；查看推广费和管理服务费发票状态、版本和历史 |

### 4.2 管理员财务端

| 路由 | 页面职责 |
|---|---|
| `/finance` | 重定向到 `/finance/promotion`，不建设财务总览 |
| `/finance/promotion` | 推广服务费单月/累计指标、发票和结算结果、厂端结果导入 |
| `/finance/management` | 管理服务费单月/累计指标、发票及扣款导入、单店修改和版本覆盖 |
| `/finance/orders/promotion` | 推广服务费订单明细、筛选、汇总和导出 |
| `/finance/orders/management` | 管理服务费订单明细、筛选、汇总和导出 |
| `/finance/stores` | 门店基础信息、SAP 建议、确认、导入和更正 |
| `/finance/disputes` | 内部管理员处理账单异议和费率纠正 |
| `/finance/imports` | 只读查询导入批次、错误、差异、覆盖关系和审计 |

导入操作从对应业务页面发起；导入记录页不直接修改业务结果。

## 5. 页面间共享事实

门店端与管理员端必须读取相同的业务事实，不允许建立两套口径：

- 当前有效账单及不可变历史版本；
- 当前有效确认记录及历史确认记录；
- 当前有效发票、账期分配行和历史发票事件；
- 当前有效导入/结算结果和更正版本；
- 异议影响范围、处理结果和关联账单版本；
- 操作者、任务、业务键、读取版本、最终版本和时间。

页面只展示后端冻结的费用结果，不在前端临时重算订单费用。

## 6. 跨页业务流程

### 6.1 门店账单确认

1. 门店进入 `/settlement`，按账期查看当前有效账单版本。
2. 推广费、管理服务费分别确认。
3. 每月 1—6 日内等待人工确认；6 日后，满足条件的当前版本自动确认。
4. 数据异常或未处理异议只影响对应费用方向和实际影响范围，不阻断另一方向。
5. 新数据、异常修复或异议结果产生新账单版本，旧版本和旧确认永久保留。

### 6.2 账单异议

1. 门店从账单或订单明细选择费用方向、账期、账单版本和争议订单。
2. 必填争议金额、异议类型、说明、联系人、手机号和证明资料。
3. 异议类型固定为费率错误、订单/数据遗漏、金额错误、其他。
4. 管理员在 `/finance/disputes` 按“待处理 → 审核中 → 待管理员审批 → 已处理”处理。
5. 处理结果只有“不成立”和“成立并调整金额”；结果直接自动确认。
6. 成立时生成新账单版本，旧版本和旧确认不删除。
7. 结果产生前可撤回并解除冻结；结果产生后只能新建纠正异议，不逆转已发生调整。

### 6.3 推广费开票

1. 门店从已确认推广费进入 `/settlement/invoice`，系统带入门店、账期和账单版本。
2. 门店在系统外开票，系统内登记购买方、6% 税率、20 位数电专票号码、开票日期和发票金额。
3. 以系统校验通过的北京时间作为登记成功时间：次月 10 日 23:59:59 及以前进入当期，11 日 00:00:00 起进入下期。
4. 状态为“待开票 → 提交成功，待厂端审核 → 审核通过，已结算 / 审核不通过”。
5. 管理员在 `/finance/promotion` 导入厂端审核和结算结果；导入结果不再审批。
6. 审核不通过时门店查看原因，在系统外红冲或作废后重新开票并登记；历史事件保留。
7. 一张推广费发票可覆盖同一门店、同一开票主体的多个完整账期；每个账期独立分配且合计严格等于发票金额。
8. 一个账期不得拆票，不得跨门店合票。负数账期不单独开票，依次抵扣最早未开票正数账期。

### 6.4 管理服务费开票

1. 管理员在 `/finance/management` 当期导入上一个业务账期，例如 10 月导入 9 月。
2. 一个门店加一个账期只能有一张当前有效发票，禁止跨账期或拆票。
3. 状态只有“待开票、已开票”，不出现推广费审核状态。
4. 信息错误时可单店修改或重新导入覆盖当前有效版本，旧版本保留。
5. 门店在 `/settlement/invoice` 只读查看本店发票、扣款、系统导入时间和版本覆盖关系，不查看导入文件。

### 6.5 SAP 与门店基础信息

1. 管理员在 `/finance/stores` 导入门店和 SAP 基线，门店 ID 是唯一匹配键。
2. 门店提交值是建议，管理员确认值才是当前有效值。
3. SAP 缺失或冲突只提示，不阻断两个费用方向的确认、开票和后续处理。
4. 新值生成版本；更正和撤销通过更正或反向版本完成。

### 6.6 导入与更正

固定四类模板：基础信息、推广费厂家结果、管理服务费厂家结果、SAP 确认。

1. 所有模板整批校验、整批写入；任一行失败则整批不写入。
2. 页面返回全部错误行，并提供分页查看和流式/分块错误文件下载。
3. 幂等采用“业务唯一键 + 标准化内容 + 文件哈希”。
4. 相同内容记录“无变化”；不同内容展示新旧差异，管理员确认后生成新版本。
5. 更正和撤销保留旧版本，不物理删除历史。
6. 原始上传文件不保存；日志保存文件名、哈希、行数、标准化结果、全部错误、差异、操作人、系统导入时间和批次关系。

### 6.7 财务查询与穿透

1. 财务页面默认单月，可切换累计。
2. 累计从 2026 年 8 月开始，包含跨期退款、差额结转和当前有效更正版本；2026 年 7 月测试数据不计入。
3. 推广费和管理服务费分别穿透到对应订单子页面。
4. 搜索、筛选必须同时作用于列表、指标、汇总和导出。
5. 导出全部命中记录，不受当前分页影响，并记录审计。

## 7. 金额与指标口径

所有金额按“分”保存，每个订单或调整行先四舍五入到分再汇总。只统计当前有效版本，历史版本只用于审计。

### 7.1 统一展示

- 已确认金额只提供单月口径。
- 账单总额、待开票金额、已开票金额提供单月与累计。
- 推广费审核通过/已结算金额和审核不通过金额提供单月与累计。

### 7.2 推广服务费

- 账单总额：当前有效推广费账单净额。
- 已确认金额：人工确认、自动确认或异议处理后自动确认的金额；未处理异议只排除影响范围。
- 待开票金额：`max(可开票的当前有效已确认金额 + 转入本期调整净额 - 当前有效发票占用金额, 0)`。
- 已开票金额：校验登记成功的当前有效发票分配金额，包含待厂端审核及已结算；不通过、红冲、作废、被替换或失效记录不计。
- 审核通过/已结算金额：当前有效结果为审核通过且结算字段完整的金额。
- 审核不通过金额：当前有效结果不通过且尚未被正确重开发票替代的金额。

### 7.3 管理服务费

- 账单总额：当前有效管理服务费账单净额。
- 已确认金额：人工确认、自动确认或异议处理后自动确认的金额；未处理异议只排除影响范围。
- 待开票金额：`max(可开票的当前有效已确认金额 + 转入本期调整净额 - 当前有效已开票金额, 0)`。
- 已开票金额：管理员导入的当前有效发票/厂家扣款金额；厂端开票与扣款使用同一完成口径。

### 7.4 订单费用

- 推广服务费金额：`推广服务费有效计费基数 × 推广服务费实际费率`。
- 管理服务费金额：`管理服务费有效计费基数 × 管理服务费实际费率`。
- 退款和取消核销生成独立负数行，不覆盖原交易。

## 8. 异常反馈与多人并发

采用“分层就地反馈”，不建设独立异常中心。

| 情况 | 用户可见反馈 |
|---|---|
| 字段错误 | 在字段旁显示错误并保留已填写内容 |
| 业务条件不满足 | 当前页顶部显示原因、影响范围和处理方式 |
| 旧版本提交 | 阻止提交并显示版本冲突，不静默覆盖 |
| 重复请求 | 返回第一次成功结果并提示已处理，不创建重复记录 |
| 导入失败 | 整批失败结果页，分页展示并下载全部错误 |
| 自动任务跳过 | 保留原状态，在详情和审计中展示跳过原因 |

版本冲突反馈至少展示业务对象、用户读取版本、当前版本、最近操作人、最近操作时间和“刷新查看最新数据”操作。

并发统一使用乐观锁、业务唯一键和幂等键。第一笔事务成功；后续旧版本操作冲突。必须覆盖：

- 两人处理同一异议；
- 两人修改同一管理服务费发票；
- 相同或不同文件并发导入；
- 页面修改与批量导入竞争；
- 自动确认与异议提交竞争；
- 审核不通过结果导入与重新登记发票竞争；
- 重复点击、超时重试和任务重跑。

## 9. 三层验收门禁

### 9.1 第一层：业务主流程

必须完整走通门店双方向确认、异议处理及新版本、推广费外部开票和系统登记、管理服务费导入、SAP 建议与确认、财务看板穿透和一致筛选导出。

### 9.2 第二层：关键业务边界

必须覆盖：

- 1—6 日人工确认和 6 日后自动确认；
- 10 日 23:59:59 与 11 日 00:00:00；
- 异议局部冻结；
- 退款金额缺失、券级映射缺失、同月和跨期退款；
- 推广费多完整账期合票、禁止拆票、禁止跨门店；
- 负数持续结转抵扣；
- 管理服务费一店一账期一票；
- 四类导入的首次、无变化、差异覆盖、整批失败和更正；
- 从 2026 年 8 月开始的单月与累计；
- 列表、指标、汇总和导出完全一致。

### 9.3 第三层：数据安全与竞争

必须覆盖门店数据隔离、管理员全局权限、全部并发场景、历史和归档审计、大批量错误分页与分块下载。

每条验收场景必须提供五类证据：

1. Given / When / Then；
2. 用户可见页面结果；
3. 接口返回；
4. 当前版本与历史版本；
5. 操作、冲突或幂等审计记录。

## 12. 规格自检结论

- 未保留业务层待确认项；实施细节均明确放入停车场。
- 页面结构、跨页流程、状态、指标、异常反馈和验收门禁相互一致。
- 推广服务费与管理服务费的状态、账期和发票规则保持分离。
- 历史财务确认稿与当前规则的冲突已明确降级为历史证据。
- 当前页面交付清单与新路由的差距已明确标注，下一步必须先回环 page-designer。
