# DYDATA-81 财务一级导航调整设计

> 日期：2026-08-28  
> 状态：已确认（用户于 2026-08-28 明确“通过，继续开发”）
> 关联需求：Linear `DYDATA-81`  
> 设计层级：模块层  
> 视觉依据：用户在本轮对话提供的现有结算中心截图，仅用于确认一级导航位置和现有界面密度；运行时视觉仍以 `docs/design-system/README.md`、`docs/design-system/tokens.json` 和现有共享组件为准。

## 1. 背景与目标

当前六个管理员财务页面已经具备稳定路由和二级导航，但在一级信息架构中仍被归入“后台”。门店账号还通过“订单分佣”二级导航中的“SAP 建议”特殊入口访问 `/finance/stores`。这导致财务业务域与系统管理域混在同一一级模块下，也让门店端出现不属于本轮结算流程的入口。

本次调整只重组现有页面的导航归属和前端准入体验：

1. 在桌面左侧一级导航新增“财务”，位置紧邻并位于“后台”上方。
2. 移动端一级导航同步新增“财务”，顺序与桌面一致。
3. 六个既有财务页面统一归入“财务”一级模块。
4. 门店账号的订单分佣二级导航移除“SAP 建议”，并取消门店账号访问 `/finance/stores` 的前端特殊放行。
5. 不新增财务首页，不修改任何财务业务、接口、数据或权限真相。

## 2. 已确认的信息架构

### 2.1 一级导航

管理员可见的一级导航顺序为：

1. 线索中心
2. 核销表现
3. 订单分佣
4. 财务
5. 后台

“财务”使用现有 Solar 账单类图标 `details`，保持一级导航可使用图标、二级导航不使用图标的 V0.2 规则。桌面侧栏和移动端底部导航复用同一份模块配置，不建立两套顺序或准入逻辑。

### 2.2 财务二级导航

点击“财务”默认进入 `/finance/promotion`。财务模块继续使用现有六项二级导航：

| 顺序 | 页面 | 路由 | 说明 |
|---|---|---|---|
| 1 | 推广服务费 | `/finance/promotion` | 财务模块默认页 |
| 2 | 管理服务费 | `/finance/management` | 保持现有页面与数据逻辑 |
| 3 | 订单明细 | `/finance/orders/promotion` | `/finance/orders/management` 继续作为页面内费用方向子路由 |
| 4 | 门店基础信息 | `/finance/stores` | 仅保留在财务模块，不再作为门店结算入口 |
| 5 | 账单异议 | `/finance/disputes` | 保持现有页面与数据逻辑 |
| 6 | 导入记录 | `/finance/imports` | 保持现有页面与数据逻辑 |

`/finance` 不承载独立页面，继续单向兼容到 `/finance/promotion`。不创建 `FinanceHomePage`，也不新增首页卡片或额外路由层级。

### 2.3 后台二级导航

后台仍只承载系统管理页面：后台首页、账号管理、分佣规则、商品口径、线索分配规则、分配试运行、分配记录、总部线索池、用户建议和数据同步。进入任一 `/admin` 页面时只激活“后台”，不得同时激活“财务”。

## 3. 导航状态模型

`Shell.tsx` 的一级模块类型从四类扩展为五类：

```text
settlement | verification | clues | finance | admin
```

路由归属按稳定集合判断：

- `/finance/*` → `finance`
- `/admin/*`、`/rule-admin`、`/sync-admin` → `admin`
- 其余既有结算、核销、线索规则保持不变

财务路由不再放入 `adminPaths`。`secondaryNav` 直接按 `finance` 返回财务二级导航，不再通过“当前是 admin 且路径以 `/finance` 开头”的条件分支推断。`sectionLabels` 增加“财务中心”，用于无障碍导航名称。

页面内已有的最长路径匹配规则继续生效，确保订单明细费用方向只有一个二级导航项处于当前页状态。

## 4. 角色与准入边界

本轮不新增 page key，也不修改后端权限模型。六个财务页面继续沿用现有 `D01` 页面权限：

| 账号场景 | 财务一级入口 | `/finance/stores` 直接访问 | 结果 |
|---|---|---|---|
| 最高管理员 / 具备 `D01` 的管理员 | 显示 | 允许 | 正常进入财务页面 |
| 不具备 `D01` 的账号 | 隐藏 | 拒绝 | 复用现有无权限页 |
| 仅具备 `B02` 的门店账号 | 隐藏 | 拒绝 | 不再把 `B02` 解释为财务门店信息权限 |

具体实现需要删除两处历史兼容：

1. `App.tsx` 中门店账号凭 `B02` 访问 `/finance/stores` 的 `hasPageAccess` 特例。
2. `Shell.tsx` 中把门店账号的 `/finance/stores` 强制归入 `settlement` 的特例。

前端拒绝只负责页面体验；后端管理员财务接口现有角色校验保持不变，本轮不以导航调整替代服务端鉴权。

## 5. 门店订单分佣调整

`settlementNavItems` 删除：

```text
SAP 建议 → /finance/stores
```

门店账号继续保留全国门店榜单、单店分账、订单费用明细和开票确认中其被授权的页面。财务“门店基础信息”页面本身不删除，管理员仍通过财务二级导航访问；页面中的 SAP 展示和管理员业务能力不在本轮修改范围内。

## 6. 视觉与响应式约束

- 桌面端只新增一个与现有 `.rail-nav__item` 同构的一级按钮，不修改侧栏宽度、按钮高度、间距、颜色、圆角或激活态。
- “财务”位于“后台”上方；截图中的空白位置只表达插入位置，不创建占位容器。
- 移动端复用 `.mobile-bottom-nav` 的均分布局。管理员场景为五个业务模块加“我的”，需在 390、768 和 1440 三个目标宽度检查标签、触控尺寸和当前页状态。
- 财务二级导航继续使用透明底文字链接和 2px 品牌橙下划线；窄屏允许横向滚动，不缩写、不增加图标。
- 不生成新图片资产，不新增自绘 SVG、CSS 图形或新的图标依赖；使用集中维护的 `SolarIcon`。
